M01L1 山脚 · 执行专员

收益管理的语言：指标与计算

11 盏知识灯
卡片·读口诀OCC 出租率：分母是可售房晚
定义/算法OCC = 已售房晚 ÷ 可售房晚 × 100%。分母必须剔除装修房与 OOO（坏房）：320 间房有 3 间 OOO，可售房晚就是 317，不是 320。
记忆要点量够不够，先剔除卖不了的房
易错点拿总房量当分母——OCC 被系统性低估。
卡片·读口诀ADR 平均房价：分母是已售房晚
定义/算法ADR = 客房收入 ÷ 已售房晚。只算卖掉的房，含服务费、不含增值税。这是 ADR 与 RevPAR 最核心的区别。
记忆要点只看卖掉的房卖得贵不贵
易错点把 ADR 的分母写成可售房晚——那是 RevPAR 的分母。
卡片·读口诀RevPAR：空房也要摊进分母
定义/算法RevPAR = 客房收入 ÷ 可售房晚 = OCC × ADR。因为要衡量「每一间可售房赚多少」，卖不掉的空房也摊进分母——这正是 RevPAR 同时被量价双向拉动的根本原因。
记忆要点收益管理第一指标
易错点认为 RevPAR 分母是已售房晚——那就跟 ADR 混了。
连线·对应概念指标 ↔ 公式（全部配对）
对应
  • OCC ↔ 已售房晚 ÷ 可售房晚
  • ADR ↔ 客房收入 ÷ 已售房晚
  • RevPAR ↔ 客房收入 ÷ 可售房晚
  • TRevPAR ↔ 总营收 ÷ 可售房晚
  • GOPPAR ↔ 经营毛利 GOP ÷ 可售房晚
  • NRevPAR ↔ RevPAR ×（1 − 渠道成本率）
排序·理清顺序指标层级：从收入到利润
正确顺序
  1. RevPAR——客房收入效率，第一指标
  2. TRevPAR——总营收效率，全服务酒店加看
  3. NRevPAR——扣掉渠道成本的真实收入
  4. GOPPAR——最终利润效率，考核指标
卡片·读口诀NRevPAR：永远不高于 RevPAR
定义/算法NRevPAR = RevPAR ×（1 − 渠道综合成本率）。成本率最低 3%（直销）、最高 26%（批发商），都 ≥0，所以 NRevPAR ≤ RevPAR 恒成立。BAR ¥680 走 OTA（16%）净收入只有 ¥571.2，比直销少 ¥88.4。
记忆要点收入要扣完渠道佣金才算数
易错点以为某渠道挂牌价高就赚得多——忘了扣成本。
卡片·读口诀三大竞争指数：量、价、合
定义/算法MPI = 本店 OCC ÷ 组合 OCC ×100（抢没抢到量）；ARI = 本店 ADR ÷ 组合 ADR ×100（卖得贵不贵）；RGI = 本店 RevPAR ÷ 组合 RevPAR ×100 = MPI × ARI ÷ 100。MPI >100 是量赢，ARI >100 是价高，别混。
记忆要点RGI = MPI × ARI ÷ 100
易错点说「MPI >100 说明卖得贵」——那是 ARI 的事。
情境·看后果用指数给自己定位
情境云璟：OCC 72.0%，组合 68.0%；ADR ¥618，组合 ¥680。三个指数各是多少？说明什么？
✅ 推荐MPI 105.9（量赢）、ARI 90.9（价低）、RGI 96.3（综合落后） → 量赢了、价输了——份额是靠低价换的。下一步不是继续放量，而是查价格定位（表 C）与产品差异，把 ADR 拉回来。
后果MPI 94.4、ARI 110.1、RGI 104.0 → 分子分母放反了。MPI = 72÷68、ARI = 618÷680，别颠倒。
后果RGI = 105.9 + 90.9 = 196.8 → 指数是相乘再除以 100，不是相加。
卡片·读口诀Pickup：预订增量，可为负
定义/算法Pickup = 某目标日在一段时间内新增的预订房晚数。为正是净新增；为负说明取消量大于新增量。它是《法典》表 A 的两个输入之一，也是表 I 六个窗口落后判定的依据。
记忆要点今天比昨天多订了还是退了
易错点把 Pickup 理解成「在手总数」——那是存量，Pickup 是增量。
情境·看后果量差与价差分解
情境3 月 OCC 74.0%、ADR ¥600；4 月 OCC 78.0%、ADR ¥660。RevPAR 涨的 ¥70.8 里，量贡献多少、价贡献多少？
✅ 推荐量差 ¥24.0，价差 ¥46.8——价贡献占 66% → 量差 = ΔOCC × ADR₀，价差 = ΔADR × OCC₁。涨价贡献更大，说明这个月主要靠价格拉动，要警惕 ADR 见顶。
后果量差 ¥28.3，价差 ¥42.5 → 权重用反了：量差用基期 ADR，价差用报告期 OCC。
后果各占一半 ¥35.4 → 不是平均分——量价各有公式，算出来就有答案。
卡片·读口诀一次完整计算走一遍
定义/算法某日售出 256 间、客房收入 ¥166,400、无 OOO：OCC = 256÷320 = 80.0%；ADR = 166,400÷256 = ¥650；RevPAR = 166,400÷320 = ¥520 = 80.0% × 650 ✓。三个数互相咬合，算完互相验一遍。
记忆要点OCC × ADR 必须等于 RevPAR
易错点只算一个数就走——三个数能互验，错了赶紧回头。
M02L1 山脚 · 执行专员

系统与数据：把术语说成同一种话

9 盏知识灯
卡片·读口诀三兄弟：MinLOS / CTA / Stop Sell
定义/算法MinLOS = 最少连住（最多住期叫 MaxLOS）；CTA = 不可入住——当日不接新到店，已住客可续住；Stop Sell（关房/停售，与 Close-out 同义）——连已住客续住一并停。三件都是《法典》表 B 的库存控制手段。
记忆要点CTA 挡新客、Stop Sell 连老人一起挡
易错点把 CTA 理解成「最多住期」。
连线·对应概念收益术语 ↔ 系统字段
对应
  • 价格代码 ↔ Rate Code / Rate Plan
  • 市场细分 ↔ Market Segment / 客源类别
  • 渠道 ↔ Channel / Source of Business
  • 价格日历 ↔ Rate Calendar / Rate Grid
  • 限制条件 ↔ Restriction / Rate Restriction
  • 免费房/自用房 ↔ Comp / House Use
卡片·读口诀价格代码 vs 市场细分：一个管价一个管人
定义/算法Rate Code 决定「卖多少钱」；Market Segment 决定「卖给谁」。云璟 7 个细分：FIT-WI / FIT-DIR / FIT-OTA / CORP / LOY / GRP / LNG。两者不可互换。
记忆要点价格代码管钱、细分管人
易错点把 Rate Code 说成市场细分——查报表时口径全错。
卡片·读口诀Source 单独出现时指什么
定义/算法系统里 Channel / Source of Business 都指渠道；但「Source」单独出现时指市场细分。一词多义，取数前先确认本系统字段定义。
记忆要点Source 独行 = 细分
易错点看见 Source 就当渠道——客源结构报表直接错位。
排序·理清顺序收益经理的一天（表 M 时点）
正确顺序
  1. 07:30 抓昨日数据 →《每日收益数据包》
  2. 07:50 抓未来 30 天在手 + Pickup
  3. 08:10 采集竞对价 → 比价表更新
  4. 08:30 查表 A/B/C/H →《今日动作清单》
  5. 09:40 价格一致性核查（6 渠道）
  6. 10:05 收益晨会
卡片·读口诀Comp / House Use 的口径
定义/算法免费房、自用房按本店政策计入已售房晚、收入计 0。政策必须写进《取数清单》。例：可售 = 320 − 5 OOO − 3 维修 = 312；已售 = 240 + 2 Comp + 1 House = 243；OCC = 77.9%。
记忆要点口径先写死，再来算数
易错点每人口径不一样——同一个酒店算出两个 OCC。
卡片·读口诀Booking Window：方向别写反
定义/算法Booking Window = 入住日 − 预订日（提前天数）。写成「预订日 − 入住日」会得负数，方向全错。六档：0–3 / 4–7 / 8–14 / 15–30 / 31–60 / >60 天。
记忆要点提前多少天订的，就是多长的窗口
易错点把窗口算成负数还照用。
情境·看后果算一个窗口落档
情境某笔预订：入住 10 月 5 日，预订 9 月 20 日。窗口多少天？落在哪一档？监控节奏是什么？
✅ 推荐15 天，落「15–30 天」档：每周 2 次，落后 20% 触发策略复盘 + 销售动员 → 对。10 月 5 日 − 9 月 20 日 = 15 天。这一档每周盯两次。
后果−15 天，窗口无效 → 方向反了：入住日减预订日，不是反过来。
后果30 天，落「31–60 天」档 → 9 月 20 到 10 月 5 只有 15 天，别把整月都算进去。
卡片·读口诀《取数清单》纪律：不多不少
定义/算法「按《取数清单》抓固定字段，不多抓一个，不少抓一个。」多抓会被无关信息干扰，少抓会让判定表读不出来。目的是让不同人、不同天取到的数据口径一致、可复现。
记忆要点口径一致 = 判定可复现
易错点凭习惯顺手多抓几个字段——表就没法查了。
M03L1 山脚 · 执行专员

每日流水线与调价：表 A 怎么查

11 盏知识灯
卡片·读口诀表 A 双因子：OCC 定方向、Pickup 定幅度
定义/算法行 = 预测 OCC（<40 到 ≥95 六档），列 = Pickup 偏差（落后 >10 / 落后 3–10 / 持平 ±3 / 领先 3–10 / 领先 >10 五档），行列交叉给出唯一动作。需求绝对水平决定方向，势头决定力度。
记忆要点先看 OCC 定调不调，再看 Pickup 调多少
易错点「Pickup 落后就要降价」——OCC 95% × 落后 5% 是 ↑5%，不是降价。
排序·理清顺序一次完整查表流程
正确顺序
  1. 定位行：预测 OCC 落哪一档
  2. 定位列：Pickup 偏差落哪一档
  3. 行列交叉读出唯一动作
  4. 合规检查：幅度 ≥3%？同日累计 ≤20%？
  5. 写台账：表编号 + 触发数值
  6. 执行后 30 分钟内查 OTA 挂牌同步
卡片·读口诀四条执行约束
定义/算法① 单日同方向累计调价 ≤20%；② 单次 ≥3%（低于 3% 无市场感知，不算调价）；③ 24 小时内同方向不超过 2 次；④ 触及 D1 峰值日的调价必须 L3 审批。
记忆要点小了不算、大了封顶、峰值要批
易错点连着降三次 8%——单日同方向已 24%，违规。
情境·看后果高频易错格：55–70 行的「持平」
情境目标日预测 OCC 66%，Pickup 持平 −1%。直觉说「不动」？
✅ 推荐↓3%——55–70% 行连持平都要求降价 → 对。需求绝对水平太低，持平也要用小降价去够需求。这是全表最高频的失分格。
后果维持——持平就是不调 → 70% 以上行「持平」才多数是维持；55–70 行持平 = ↓3%。
后果↓5% → 幅度大了：这格是 ↓3%。
情境·看后果落后但不降价的格子
情境预测 OCC 95.5%，Pickup 落后 5%。查表 A。
✅ 推荐↑5%——OCC 已过 95%，方向是提 → 对。OCC 定方向：高需求日即便势头落后也提价，只是幅度收着。
后果↓5%——落后就降 → 双因子：OCC 定方向，Pickup 只定幅度。
后果维持 → 95.5% ≥ 95% 行没有「维持 × 落后 3–10%」这个组合。
情境·看后果唯一的「领先仍降价」格
情境预测 OCC 32%，Pickup 领先 5%。查表 A。
✅ 推荐↓5%——OCC 太低，领先也救不回来 → 对。这是全表唯一「领先仍降」的格子：<40% 行 × 领先 3–10% 列。最高频失分点之一。
后果↑5%——领先就该提 → 需求绝对水平 32%，提价等于把客人往外推。
后果维持 → 这一格不是维持——是 ↓5%。
连线·对应概念OCC 档 ↔ 典型方向
对应
  • ≥95% ↔ ↑5%–20% 满房逻辑
  • 85–95% ↔ 多为 ↑3%–15%
  • 70–85% ↔ 小幅 ↑ 或 ↓3%
  • 55–70% ↔ ↓3%–5% 或维持
  • <40% ↔ ↓10%–20% 最大力度
情境·看后果表 A 给了「维持」之后
情境预测 OCC 96%，Pickup 落后 15%。表 A = 维持。这一天就什么都不做了？
✅ 推荐顺延执行下一优先级：查表 C（ARI），再表 H（渠道）；表 A 的维持记入台账备注 → 对。表 O 铁律：最高优先级为「维持」时顺延，不是收工。
后果维持就是今天的最终结论 → 那是表 A 单表的结论；全店动作要按表 O 顺延。
后果直接提价 → 表 A 明确维持时不能自作主张提价——顺延看别的表。
卡片·读口诀D1 峰值日：L1 不能自己拍板
定义/算法国庆 1–5、五一 1–3、春节初三–初六 + 展会共约 20 天，价格系数 150–200%、目标 OCC ≥95%。触及 D1 的调价必须由 L3 收益经理审批，L1 无权自调。
记忆要点峰值日的价格 = 钱最多的地方 = 审批最严
易错点L1 觉得方向对就直接执行——流程违规。
情境·看后果国庆 D1 实战
情境10 月 2 日（D1）预测 OCC 92%，Pickup 领先 12%。L1 小王查得 ↑15%，准备直接执行。
✅ 推荐动作 ↑15% 没错，但必须 L3 审批后执行 → 对。D1 触发审批约束。审批通过后执行并写台账：表 A：OCC 92% × 领先 12% → ↑15%，D1 日，L3 已审批。
后果D1 不能调价，放弃 → D1 不是不能调，是必须审批。系数 150–200% 本来就是为峰值准备的。
后果再叠加提 5% 凑 20% → 单日同方向累计 ≤20%，且叠加执行本身违规。
卡片·读口诀17:00 二次巡检：尾房时刻
定义/算法表 M 17:00 = 二次巡检（0–3 天窗口），15 分钟。对应表 I 唯一用绝对值的档：OCC <70% → 上「今日特惠」尾房产品。因为临期已来不及调价修复，只能用产品直接清库存。
记忆要点最后 3 天不看百分比，看绝对出租率
易错点0–3 天还在研究调价——来不及了，上尾房产品。

报表与台账：留下可复盘的痕迹

8 盏知识灯
连线·对应概念表 N 周期 ↔ 产出物
对应
  • 每周一 ↔ 《周度收益报告》
  • 每周三 ↔ 比价深度表
  • 每周五 ↔ 《周末作战表》
  • 每月 1 日 ↔ 《月度收益复盘报告》
  • 每月 5 日 ↔ 《客源渠道报告》
  • 每月 10 日 ↔ 汇报 PPT + 一页纸摘要
  • 每年 9 月 ↔ 《年度预算文件》
卡片·读口诀每周一的三件事
定义/算法房型价差校验（表 F）+ 未来 8 周预测更新 + 渠道开关复核（表 H）→《周度收益报告》。相邻价差 <8% 拉开、>35% 收敛——校验就是查这两条。
记忆要点周一 = 校准日
易错点把比价（周三）或周末盯防（周五）的事放到周一。
卡片·读口诀每月节奏：1 → 5 → 10
定义/算法1 日对内复盘（RGI/MPI/ARI 三维诊断 + 滚动预测）；5 日客源结构与渠道贡献分析；10 日对业主/管理层汇报。先内部消化，再对外汇报。
记忆要点先对内、后对外
易错点1 日就出《客源渠道报告》——那是 5 日的事，差 4 天。
卡片·读口诀《调价台账》13 个必填字段
定义/算法操作日期、目标入住日、房型代码、渠道、原 BAR、新 BAR、调价幅度%、依据表编号、预测 OCC、Pickup 偏差、操作人、复核人、备注。竞争组合挂牌价不在其中——那记在比价表里。
记忆要点依据栏 = 表编号 + 触发数值
易错点依据栏写「市场变化」——模糊表述，上机扣 3 分。
卡片·读口诀没执行的结论更要记
定义/算法表 O 铁律第三条：所有冲突与取舍必须写入台账备注栏。被放弃的那条结论（比如表 A 维持、顺延执行了表 C）恰恰是复盘时最需要的信息。
记忆要点留痕是为了让一个月后的自己看懂今天
易错点只记执行了的动作——复盘时说不清当时为什么这么定。
卡片·读口诀三维诊断：份额、价格、综合
定义/算法MPI 看份额（表 D）、ARI 看价格定位（表 C）、RGI = MPI × ARI ÷ 100 看综合。三者结合才能识别「假持平」：RGI 100 = MPI 106 × ARI 94，是低价换来的份额。
记忆要点一个指数下结论，三个指数才定论
易错点RGI 100 就宣布追平市场——可能是拿利润换的。
情境·看后果台账扣分计算
情境上机实操：台账漏填 2 个字段、未标注依据表编号。该项满分 10 分（每缺 1 项扣 1 分、无表编号另扣 3 分），得多少？
✅ 推荐10 − 2 − 3 = 5 分 → 对。先扣缺项，再扣表编号专项。写不出表编号的记录，在笔试里同样扣分。
后果7 分 → 漏了表编号的专项扣 3 分。
后果0 分——扣完为止 → 还没触底：8 − 3 = 5，不到 0。
卡片·读口诀一年 197 份报表

记忆要点维度不同，并行不悖
易错点把团队询价也卷进表 O 顺延——该接的单被拖着黄了。
情境·看后果总经理令：今天必须降 20%
情境预测 OCC 64%、Pickup 落后 16%。查表 A = ↓10%。总经理晨会拍板降 20%。
✅ 推荐按表 A 执行 ↓10%：向总经理展示查表依据，说明 20% 一次用满当日额度、且超出表格结论无台账可写 → 对。用表格与约束说话：不是不听指挥，是 20% 之后今天再无调整空间，且 10% 已是该格结论。

情境·看后果业主的 ARI 幻想
情境业主：「我们要做高端，ARI 必须从 90.9 提到 110，不能比竞对便宜。」当前 ADR 618、组合 680。

后果答应，明天就提价 → 21% 直接违反表 C 约束，OCC 崩盘后业主第一个问责。
后果说「做不到」 → 只有拒绝没有方案——给出渐进路径（分季提价 + 产品升级）才是专业应答。

记忆要点先高卡后低卡、先长住后短住

情境·看后果财务总监的风险质疑
情境「超售是赌客人不来，这是风险敞口，我不同意。」历史 No-show 6% + 取消 7% = 13% → 基准 3%；320 间预测 96% 档修正后 9 间。怎么应答？

后果「大家酒店都超售」 → 同行惯例不能回应风险质疑——要给数字。
后果「出了事有预案」 → 只谈兜底不谈收益，等于承认纯风险。期望账才是完整答案。

排序·理清顺序RMS 四模块（按数据流）

  2. 需求预测：历史 + 在手 + 提前窗口 → 每日预测

  4. 自动下发：推到 PMS 与各渠道
卡片·读口诀白名单/黑名单判据
定义/算法白名单 = 错了代价可控且易回滚（平峰 ±3–5%、常规开关、限制批量设置、巡检、报表）。黑名单 = 错了代价高或需人的判断（D1 日任何调价、超售率 >10%、团队会议询价、表 L 异常事件）。
记忆要点错了赔得起才交给机器
易错点按「涉不涉及钱」分——平峰调价也涉及钱，但赔得起。
连线·对应概念动作 ↔ 白/黑名单
对应
  • 平峰日 ±3–5% 调价 ↔ 白名单
  • 常规渠道开关 ↔ 白名单
  • D1 峰值日调价 ↔ 黑名单
  • 超售率 >10% ↔ 黑名单
  • 团队/会议询价决策 ↔ 黑名单
  • 价格一致性巡检 ↔ 白名单
卡片·读口诀为什么 D1 不能全自动
定义/算法全年约 20 个 D1 日占客房收入 12–18%，调错一次几十万且无法回滚；且系统在 D1 的一手数据最少（一年才几次），预测误差反而最大。D1：系统只给建议，人来拍板。
记忆要点越值钱的日子，人越要在场
易错点「系统国庆预测最准」——恰恰相反，样本最少的日期误差最大。
卡片·读口诀告警稀缺性：只留 8 条
定义/算法告警太多等于没有——人会把邮箱设成自动归档。只留真正需要人介入的：Pickup 异常落后/领先、ARI 越界、一致性违规、接近满房、渠道断连、竞对大幅降价、超售逼近上限。其余走日报。
记忆要点告警的价值在于稀缺
易错点「宁可误报不可漏报」配 80 条/天——第三天就没有人看了。
排序·理清顺序自动化渐进五级（不许跳级）
正确顺序
  1. L0 纯手工
  2. L1 Excel 半自动（建议所有人从这里开始）
  3. L2 系统推荐 + 人工确认（150 间以上或有专职收益）
  4. L3 白名单自动 + 黑名单人工（L2 顺跑 3 个月以上）
  5. L4 全自动 + 人工监管（集团多店 + 成熟中台）
情境·看后果跳级的代价
情境某店从 L0 直接上 RMS 开全自动，一个月 ADR 掉了 15%。
✅ 推荐典型跳级事故：参数没配好 → 建议离谱 → 全自动没人看。回退到 L2：推荐 + 人工确认，顺跑 3 个月再放白名单 → 对。自动化不是一步到位，采纳率 >70% 才升级——每一级是下一级的验收。
后果系统不行，换一家 → 先查参数与流程：多数「系统不行」是 L0 直接跳 L4 的人为事故。
后果关掉系统回到手工 → 因噎废食。回退一级（L2）保留预测能力，人审价格。
卡片·读口诀12 个参数必须自己算
定义/算法竞组、价格地板（盖住变动成本）、细分权重（按净贡献不按产量）等 12 参数不能照抄推荐值——每家店的成本结构与客群不同。且每季度复核一次，市场变了参数不改，系统越跑越偏。
记忆要点参数是系统的大脑，得自己喂
易错点抄隔壁酒店的参数——系统学的是别人家的生意。
情境·看后果系统学坏了
情境按「产量」设细分权重三个月，NRevPAR 越跑越低，系统天天降价冲 OTA。
✅ 推荐权重口径错了：改成按净贡献设——直销 3% 权重应高于 OTA 16%；重训参数 → 对。产量最大 ≠ 贡献最大。按产量设权重等于告诉系统「OTA 的量最值钱」。
后果OTA 单也赚钱，没问题 → 16% 佣金下的「赚钱」被直销 3% 一比就露馅——NRevPAR 已经在报警。
后果关掉自动调价 → 先修参数（根因），再谈开关——参数错，人工确认也会被带偏。
情境·看后果国庆 D1 系统建议降价
情境国庆 D1，系统建议降价 10% 冲 OTA（预测 OCC 仅 82%）。执行吗？
✅ 推荐不执行——D1 任何调价在黑名单，人工拍板；先人工复核预测：D1 历史 OCC ≥95%，系统 82% 大概率低估 → 对。黑名单挡下动作 + 人复核预测——两层都指向「不执行」。
后果执行——系统基于数据 → D1 是黑名单；且预测 82% 与 D1 历史规律矛盾，输入可能就错了。

卡片·读口诀超售参数：两个上限取小

记忆要点参数抄法典，别自由发挥
