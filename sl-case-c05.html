案例 05 · 展会周的那 300 间房

杭州滨江云璟酒店 · 第 0 篇 ｜ 共 11 屏
<b>引子</b>：国际博览中心办大展，四天。郑昊手里攥着一个 200 间的长期客户，报价 620——接还是不接？

情境：这一夜到底发生了什么

三月，滨江国际博览中心办一场医疗器械大展，展期四天（周三到周六）。按往年经验，这是云璟酒店全年最好的四天之一。

展会前第八天，林岚把在手表摊在桌上：

小马看了就急："比去年少这么多，是不是要降价？"

"先看 Pickup。"林岚调出另一张表——近七天每日新增的间夜数：

"在手比去年低，但涨得比去年快。"林岚说，"展会的预订特点是临期爆发——客人确认行程晚，越靠近展期下单越猛。去年最后八天一共涨了 249 间，今年按这个速度，最后八天能涨 300 间以上。"

她按下计算器：

预测结论：周四、周五将满房甚至超订，周三接近满房。

"所以不是要降价，"林岚说，"是要提价，而且要关门。"

同一天下午，郑昊来了。

他手里的单子很厚：一家长期合作的医疗器械公司，展会期间要 200 间/晚，连住 3 晚，出价 620，外加一个大宴会厅做晚宴（120 人）。

"老客户了，三年了。"郑昊说，"他们预算就这么多。接不接？"

"日期？"——周三、周四、周五。

"房型？"——高级房 140、豪华房 60。

"去年这单我们收多少？"——郑昊翻记录：去年是 580 一间，也是 200 间。

"今年他们涨到 620 了。"郑昊说，"我觉得可以接。"

林岚打开置换分析⑧表，一边填一边念：

团队总贡献：

被置换的散客价值：

关键在——这三天如果不给团队，散客能卖多少？

林岚调出去年展会三天的散客成交价：平均 812 元，OCC 94%。今年按在手速度，预测四天平均可达 780–880。

被置换 = 600 间夜 × (812 − 95) = 430,200 元

净置换收益 = 411,000 − 430,200 = −19,200 元

"负数。"林岚把屏幕转给郑昊，"这单接了，比不接少赚一万九。"

郑昊不服："可他们是长期客户，明年还来。"

"长期客户更要谈清楚。"林岚说，"你把总账算给他看：宴会厅我们给，房费按 780 谈，或者——"

她想了想，给了另一个方案：

"方案二：只接周三和周六，各 100 间。这两天预测分别是 293 和 260，压力小；周四、周五留给散客，这两天是我们全年最贵的两天。"

情境：这一夜到底发生了什么

郑昊算了一下：

被置换（周三、周六散客价约 720）：200 × (720 − 95) = 125,000 元

净置换收益 = +76,000 元

"这个能接。"林岚说。

"可客户要三天连住。"

"那就告诉他：周四、周五我们给不了，因为那两天满房。这是实话，不是推脱。他要连住，可以周三到周五住我们这儿、周五挪到隔壁 C 店——我查过，C 店周四、周五还有房。我们帮你协调。"

郑昊愣了半天："你还帮客户找别家？"

"他们三年都来，是因为我们办事靠谱，不是因为我们便宜。"

展会周最后的结果：

四天 RevPAR③ 平均 792，比去年同期的 726 涨了 9.1%；因为关掉了低价档并设了"最短住期 2 晚"，间夜数只少了 21 间，GOP 同比涨了 13%。

郑昊那个客户，最后按方案二接了周三、周六各 100 间，宴会照做。客户临走时跟郑昊说："你们今年帮我们安排了 C 店，这事办得漂亮。"

决策点 · 你会怎么选

决策点一：在手比去年低，就要降价吗？

  • 不能只看在手，要看 Pickup（在手增长速度）
  • 判据：在手是存量，Pickup 是增速。展会这类临期爆发的需求，看增速。

决策点二：预测满房之后，先做什么？

  • 顺序：① 关低价档 → ② 设最短住期⑪ → ③ 提价
  • 判据：限制条件优先于价格——先别让便宜的房占掉库存，再谈卖多少钱。

决策点三：长期客户的大单接不接？

  • 用置换分析⑧，按天拆开算（不要三天一起算）
  • 判据：同一单在不同日期的结论可能相反——淡日可接，旺日不可接。

决策点四：客户要连住但某天满房，怎么办？

  • 选项 A：硬接（亏钱）
  • 选项 B：拒绝（伤关系）
  • 选项 C：部分接 + 帮客户协调周边酒店（林岚的做法）
  • 判据：长期关系的价值不在价格让步，在办事可靠。

知识提炼

一、需求预测的三个来源

来源看什么适用
历史同期去年同日/同事件的最终 OCC、ADR稳定需求
当前在手已确认的间夜所有场景
Pickup（增速）近 7 日新增间夜 vs 去年同窗口展会/事件日（临期爆发）

预测公式（简化）：

```

预测最终在手 = 当前在手 + 去年同窗口 Pickup × 今年增速系数

```

本例：周三 218 + 61 × 1.2 ≈ 291（实际 288，误差 1%）

判定表 · 该看哪个源

| 情境 | 主要依据 | 辅助 |

|---|---|---|

| 平常日 | 历史 + 在手 | Pickup |

| 展会/事件日 | Pickup 增速 | 历史同期 |

| 首次事件 | 类比同类事件 | 保守打折 |

二、Pickup 的"对角读法"

在手表里，同一目标日期在不同统计日的数字排成一列，看它每天的增量：

```

目标日：周三

T-8：218

T-7：235 (+17)

T-6：251 (+16)

T-5：268 (+17)

...

```

看的是这一列往下走的斜率，不是单个数字。斜率在变陡 = 需求在加速 → 提价；斜率变平 = 需求乏力 → 观察。

三、展会日的三道限制条件

限制作用本例设置
关闭低价档不让便宜的房占库存关高级房 620 以下所有档
最短住期 2 晚挡住只住一晚的客人周四、周五设 MLOS 2
房型保护给高价房型留量套房、行政房只开放给高价渠道

三道闸的顺序不能反：先关档 → 再设最短住期⑪ → 最后提价。

四、置换分析要"按天拆"

```

净置换收益（第 N 天）= 团队当天贡献 − 被置换散客当天价值

总净收益 = Σ 每天的净收益

```

本例：

  • 周三 +、周四 −、周五 −、周六 +
  • 三天一起算 = −19,200（拒）
  • 分天算：周三、周六接 = +76,000（接）

判定表 · 团队询价

| 情况 | 结论 |

|---|---|

| 全部日期净收益 > 0 | 全接 |

| 部分日期 > 0 | 只接正收益的那些天，其余帮客户协调 |

| 全部 < 0 | 不接，或抬价/换日期 |

五、预测误差要记账

预测完之后，把预测值和实际值记下来，算 MAPE（平均绝对百分比误差）：

```

MAPE = 平均(|预测 − 实际| ÷ 实际) × 100%

```

本店目标：展会日 MAPE < 8%，平常日 < 12%。

误差持续偏大，就说明这个情境的历史数据不能用，要换类比对象。
