2. 当前计算方法的错误与疏漏

错误一：用「房费收入」而非「净贡献」

07-displacement.xlsx 直接比房费：团队收入 50×380=19,000，散客损失 50×520=26,000，净 −7,000。这忽略了变动成本（布草/水电/清洁）与餐饮等非客房贡献。团队房价低，但变动成本也低、且常带来餐饮/会议收入；散客房价高，但变动成本与餐饮贡献结构不同。比房费会系统性高估团队、误拒合理业务。

错误二：100% 置换假设（忽略售罄概率）

旧工具把「被挤占散客房量」直接等于团队量（B7=50 硬编码），等于假设酒店每晚都满房、每间团房都挤掉一个付费散客。当酒店有空房（需求 < 容量−团队量）时，接受团队零置换、应直接接受；旧算法仍判「损失散客」，导致误拒。AHLEI-CHRM 的关键修正即引入置换因子 ρ = 预测出租率：并非每个团队房都真挤掉一个散客。

疏漏三：缺少 wash 率（团队未到/取消率）

团队报价常含 5%–15% 的未到/取消。直接用申请量算占用与置换，会高估团队占用、高估置换。正确做法：实际到店房晚 = D_grp × (1 − wash)。

疏漏四：单收入流，忽略餐饮/会议等其他净利润贡献

旧模型只有房费（+可选 F&B）。会议、宴会、健身、停车等「其他净贡献」未计入边际贡献，使群体与散客的真实贡献被低估/错估。国际通行用全口径净贡献，且分子分母口径必须一致。

疏漏五：缺安全边际与 bid price（容量机会成本）

预测有误差。国际通行给群体贡献预留 ≥10% 安全边际：净贡献须 ≥ 散客损失×(1+s) 才接受，否则还价或拒绝。此外，若这些房留作更高价业务（bid price / 保留房机会成本），置换的散客房应按 MAX(散客贡献, bid) 计价，抬高接受门槛。旧模板两者皆缺。

小结：最大问题不在「公式写错」，而在口径不自洽——表 G（v2026.2）已是正确权威版，但 calc-displacement.xlsx 只做到一半、07-displacement 仍用错误老法，导致全站置换分析结论不可信、且各页互相矛盾。

4. 新计算方案（v2026-6）

4.1 输入参数

R_total 总房数D_trans 散客期望需求D_grp 团队申请量ADR_t 散客均价ADR_g 团队报价VC 变动成本F&B_t/g 餐饮净贡献Other_t/g 其他净贡献wash 率ρ 预测出租率s 安全边际bid 保留房机会成本肩部夜调整

4.2 公式体系

C_t = (ADR_t − VC) + F&B_t + Other_t // 散客每间夜边际贡献 C_g = (ADR_g − VC) + F&B_g + Other_g // 团队每间夜边际贡献 G_eff = D_grp × (1 − wash) // 团队实际到店房晚 约束置换 = MAX(0, D_trans − (R_total − G_eff)) // 需求超出剩余房的部分 ρ折上限 = G_eff × ρ // AHLEI 概率法上限 Displaced = MIN(ρ折上限, 约束置换) // 实际置换；酒店有空房→0 团队贡献 = G_eff × C_g 散客损失 = Displaced × MAX(C_t, bid) + 肩部夜调整 净贡献 = 团队贡献 − 散客损失 判定 = 散客损失=0 ? 直接接受 : (净贡献 ≥ s×散客损失 ? 接受 : 拒绝) ADR_g(min) = VC − F&B_g − Other_g + Displaced×MAX(C_t,bid) / G_eff // 盈亏平衡团价 还价底线 = ADR_g(min) × (1 + s)

4.3 算例对比（同口径输入：300 房，散客 280@618，团队 60@480，VC 120，F&B 90/70，其他 40/30，wash 10%，ρ 92%，s 10%）

方法关键计算结论
旧·纯房费+100%置换团收 28,800；损 60×618=37,080；净 −8,280误拒 ✗
旧·净贡献(无wash/ρ/安全)C_t 588 / C_g 430；置换 40；净 2,280接受（无安全冗余）
新·v2026-6C_t 628 / C_g 460；G_eff 54；约束置换 34；ρ上限 49.68；置换 34；团贡 24,840；损 21,352；净 3,488；安全阈值 2,135接受 ✓（过 10% 安全）

4.4 情景二：低出租率有空房（最易被旧法误拒）

参数同上，仅 D_trans=200、ρ=0.60。剩余散客房 = 300−54 = 246 > 200 → 约束置换=0 → 置换=0。

方法结论
旧·纯房费+100%置换仍判 −8,280 → 误拒 ✗（假设满房挤占，错）
新·v2026-6有空房·直接接受 ✓（净贡献 24,840，零置换）

4.5 情景三：高 wash 使团队更划算

默认参数，wash=30%。G_eff=42，约束置换=22，ρ上限=38.64 → 置换 22；净贡献=5,504（高于默认 3,488），盈亏平衡价降至 ¥349。说明 wash 率显著改变决策——旧法完全忽略。
