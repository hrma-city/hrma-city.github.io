系统与数据导航

一句话导语：不管你店上跑的是哪套 PMS，收益专员要抓的字段是固定的——本模块把「要找什么数据、它一般叫什么、几点前必须抓完」钉死，并给你一套脏数据排查方法，保证喂给判定表的每一个数都是干净的。

  • 能完成 4 条数据一致性恒等式自检，且在发现不等时说出排查顺序

一、为什么讲「系统无关」：字段是固定的，菜单是会变的

本学院不教某一个品牌系统的按钮在哪，原因有三：

1原因一

你不知道学员店上跑的是哪套系统。云璟酒店集团 38 家在营门店就可能同时存在多套 PMS。教按钮，等于教了一条上任第一天就失效的知识。

2原因二

同一套系统不同版本，菜单位置会变；同一版本不同门店的权限配置，可见菜单也会变。路径不可靠，功能名与字段名可靠。

3原因三

《法典》判定表的输入是字段值（预测 OCC、Pickup 偏差、在手房晚），不是菜单。学会抓字段，换系统当天就能上岗。

系统无关的唯一写法

正确写法：「在价格日历中，把目标日 SUP-K 房型的 BAR 从 ¥680 调整为 ¥748。」
错误写法：「点击 Opera 的 Rate Grid 按钮，在第三列输入 748。」
判断标准：把这句话拿给一个用西软的同事看，他能照做，就是系统无关；他问「按钮在哪」，就是系统有关。

二、四套编码体系：一条订单的完整身份证

任何一笔订单，在 PMS 里都由四个编码共同描述。缺任何一个，这笔业务就无法被正确归因，后面所有的 OCC/ADR/渠道分析都会偏。

房型代码
卖的是什么房间
例：SUP-K 高级大床房
＋
价格代码
按什么价格规则卖
例：BAR 最优可用房价
＋
市场细分
客人是谁
例：FIT-OTA OTA 散客
＋
渠道代码
从哪条通路进来
例：OTA 国内（16% 成本）
四个编码常犯的一个错

把「市场细分」和「渠道」当成一回事。举例：一位协议公司员工通过携程预订——市场细分是 CORP（人是谁），渠道是 OTA（从哪来，成本 16%）。如果只记成 CORP，NRevPAR 会按 8% 成本算，实际是 16%，一进一出偏差 8 个百分点。
判定口诀：细分看「人」，渠道看「钱从哪条路进来」。

房型代码的 3 个取数纪律

1. 房型代码必须写全，不许简写。「高级房」是 SUP-K + SUP-T 两个代码共 100 间，写「高级房」会让房晚统计差 40 间。

3. 12 间无障碍连通房不单列房型代码。它们分布在 STD 与 SUP 房型内，通过「房态属性/房间特征」字段标记，取数时用该属性过滤，不要自建房型代码。

价格代码最容易出的三个事故

1. BAR 只改了一个房型。调 ↑10% 时只改了 SUP-K，忘了 SUP-T / DLX-K / EXE-K。后果：房型价差阶梯被破坏，触发《法典》表 F「相邻房型价差 <8% → 拉开价差」。处置：调价必须按《房型价差阶梯表》整表落位，逐个房型核对。
2. COMP 挂了 BAR 代码。免费房用了 BAR 价格代码、收入填 ¥0。后果：ADR 分母虚增，ARI 被低估。处置：凡是收入为 ¥0 的订单，价格代码必须是 COMP。
3. MEMB 未设登录可见。会员价被未登录用户抓到并比价。后果：违反《法典》表 H 价格一致性红线，24 小时内必须整改并记入考核。处置：每周一渠道开关复核时逐渠道验证一次会员价可见性。

细分代码不是「随便选一个」

细分代码决定三件事：① 该笔房晚计入哪个细分占比；② 该笔业务是否触发置换分析（GRP 必查表 G）；③ 该笔业务走哪条渠道成本（影响 NRevPAR）。
冲突判定：当一笔订单同时符合两个细分时，按「更严格」的一个归类。例：一位协议公司客人以团队形式预订 12 间 → 归 GRP（因为 GRP 需要走表 G 置换分析，更严格），不归 CORP。

取完数、查表之前，必须先跑这 4 条自检。任何一条不成立，禁止进入查表环节——因为带着脏数据查表得出的动作，比不查表更危险。

#恒等式不等时的排查顺序
1 已售房晚 = Σ10 个房型房晚 = Σ7 个渠道房晚 = Σ7 个细分房晚 ① 检查导出时是否漏选房型/渠道；② 检查是否有订单缺失渠道或细分字段（空值）；③ 检查 Comp / House Use 是否被同时计入两个渠道

口径校验
¥691.7 与《SPEC》平峰加权均价 ¥680 偏离 (691.7−680)÷680 = ↑1.7%，未超 8% 阈值 → 采集口径可信
算指数
本店 ADR ¥724.8（付费口径）→ 但竞对采集的是「不含早 · 免费取消」口径，本店须用同口径 BAR ¥680 对比
ARI = 680 ÷ 691.7 × 100 = 98.3 → 落《法典》表 C「97–103 健康」→ 维持
本示范的三个关键动作

1. 先自检再查表：4 条恒等式全部跑通才进入 08:30 查表环节。
2. 修正必留痕：3 条《数据修正记录》全部编号归档，30 天后复盘可追溯。
3. 口径对齐后再比价：ARI 计算前先把本店 ADR 换成与竞对同口径（不含早、免费取消、SUP-K 同档位），否则 98.3 会算成 104.8，表 C 判定从「健康」跳到「略高」，结论完全不同。

跟练 2 · 房型代码与价差
导出某日房型房晚：STD-K 68、STD-T 48、SUP-K 55、SUP-T 38、DLX-K 42、DLX-V 14、EXE-K 24、EXE-T 5、STE-B 8、STE-E 2。请做两件事：（1）校验合计是否为 320；（2）指出这份数据其实不是「房晚」而是「可售间数」，说明理由。
查看答案与解析
（1）合计 = 68+48+55+38+42+14+24+5+8+2 = 304，不等于 320 → 数据不完整，有 16 间缺失。
（2）理由：每个房型的数字都≤该房型的总间数（STD-K 68 ≤ 70、SUP-K 55 ≤ 60…），且没有出现 0，这更像是「可售间数」而非「已售房晚」。已售房晚通常会明显低于总间数且可能出现 0（如 STE-E 只有 2 间，淡季完全可能售 0）。
处置：回到 PMS 重新选择报表的「统计口径」字段——选「Sold Room Nights 已售房晚」，不要选「Available Rooms 可售间数」。这是最常见的取数事故之一。

第 3 题
下表是某日导出数据，请先做恒等式自检，再回答：能否进入 08:30 查表环节？
总房量 320、OOO 8、可售房晚 312、已售房晚 240、房型合计 240、渠道合计 240、细分合计 240、客房收入 ¥163,200、细分收入合计 ¥163,200。
查看答案与解析
恒等式 1：已售 240 = 房型 240 = 渠道 240 = 细分 240 ✓
恒等式 2：客房收入 163,200 = 细分收入 163,200 ✓
恒等式 3：可售 312 = 320 − 8 ✓；已售 240 ≤ 可售 312 ✓
恒等式 4：本题未给竞对数据，需补充后跑（MPI/ARI/RGI 三项）。
结论：在补充竞对数据、跑完恒等式 4 之前，不能进入查表环节。因为《法典》表 C（ARI）需要竞争组合加权 ADR 作为输入，缺了它表 C 无法查，而表 C 与表 A 的冲突仲裁（《法典》表 O）也就无从进行。
第 4 题
采集到 5 家竞对价：A ¥650（280 间）、B ¥690（240 间）、C ¥560（300 间）、D ¥880（350 间）、E ¥620（200 间）。求按房量加权的竞争组合加权 ADR；若本店同口径 BAR 为 ¥680，求 ARI 并说明落在《法典》表 C 的哪一档、动作是什么。
查看答案与解析
加权分子 = 650×280 + 690×240 + 560×300 + 880×350 + 620×200 = 182,000 + 165,600 + 168,000 + 308,000 + 124,000 = 947,600
加权分母（房量合计）= 280 + 240 + 300 + 350 + 200 = 1,370
竞争组合加权 ADR = 947,600 ÷ 1,370 = ¥691.7
ARI = 680 ÷ 691.7 × 100 = 98.3
《法典》表 C：98.3 落在「97–103 健康」档 → 动作 维持。
解析：注意 ARI 必须用同口径对比——本店用不含早、免费取消、SUP-K 同档位的 BAR ¥680，竞对也必须按同样条件采集。若本店误用含早口径（BAR + ¥68 = ¥748），ARI 会算成 108.1，落到「103–110 略高」，结论变成「维持，观察 Pickup」，看似相近实则掩盖了真实的价格位置。
第 5 题
判断改错：某收益专员说「我们店用的是西软，所以 M03 教的调价步骤我有一部分做不了，因为路径不一样」。请指出这句话的错误，并给出正确做法（3 个动作）。
查看答案与解析
错误：把「路径不同」当成了「动作不同」。M03 教的是系统无关的动作（把目标日 SUP-K 的 BAR 从 ¥680 调整为 ¥748、设 MinLOS 2 晚、关闭 WHO 渠道），不是某个系统的按钮位置。任何一套 PMS 都具备这三项功能，只是菜单位置不同。
正确做法（3 个动作）：
① 在表 2-7《主流系统操作路径映射表》中定位通用动作（如「① 打开价格日历」），查西软列 →「房价管理 → 房价计划 → 房价日历」。
② 若按路径找不到：先在西软内搜索功能名关键词（「房价」「限制条件」「停售」）→ 再问门店系统管理员。
③ 找到后把本店实际路径补写进表 2-7，形成本店版本，并在《调价台账》中按系统无关表述记录动作，不写按钮名。
判定标准：把这句话拿给一个用 Opera 的同事看，他能照做，就是合格的动作描述。
