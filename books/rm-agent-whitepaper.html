RMC 收益管理智能体 · 产品白皮书

从「判定表教练」升级为「可自主决策的 AI 产品」
版本 v0.1 工作稿 · 2026-11-05 · 仅内部评审与申报使用（noindex）
一句话定位：RMC 智能体是一个接入酒店实时经营数据、自动预测需求、优化价格与房量、并能用自然语言解释「为什么」并持续学习的收益管理决策智能体。15 张判定表、41 章教材、76 套真题不是产品本身，而是智能体的训练数据、评估基准与治理护栏。

一、为什么「判定表教练」不是 AI

判定表的本质是一个确定的策略函数 π：输入市场状态 S → 输出决策 D。只要 S 是数字，Excel 一个公式就能算出 D，网页表单只是把"打开 Excel"换成"打开网页"。它不具备以下特征：

  • 不学习（表不变，结果永远不变）；
  • 不推理（只给结论，不解释权衡）；
  • 不处理未知状态（表外即空白）；
  • 要人工录入（无法自动获取 S）。

因此评审会直接判定：这是计算器界面，不是 AI 产品。要拿 AI 为主的 OPC 奖金，必须把产品主角从"知识交付"换成"自主决策智能体"。

维度判定表网页 / Excel真正的 RM 智能体
数据来源人工录入 S自动接入 PMS / OTA / 竞品 / 事件
决策方式查表（确定性）预测 + 约束优化（概率 + 求解）
未知状态表外即空白泛化 + 推理
解释能力只给结论给「为什么」+ what-if
自主闭环你问它答监测 → 建议 → 执行 → 学习
是否越用越聪明否是

二、真·智能体的五层能力（Excel 做不到的）

LAYER 1

自动数据接入

从酒店系统（PMS、携程/美团/Booking、竞品房价、本地展会与天气）持续拉取，自己拼出市场状态 S。免手填本身就是工程价值。

LAYER 2

需求预测（不确定性）

按日期 × 细分市场预测入住 pace、取消率，输出概率区间而非死数。这是机器学习，不是查表。

LAYER 3

价格 / 房量优化引擎

在超售上限、最小连住、团队房控等约束下，求解使期望收益最大的价格梯队——运筹优化，静态表无法覆盖连续价格与交互效应。

LAYER 4

自然语言推理与解释

"为什么 12/24 建议你降价？""会展取消会怎样？"能对话、能 what-if、能读竞品评论与新闻等非结构化信息。

LAYER 5

人在环执行闭环

提建议 → 护栏内可自动下发渠道 → 监测结果 → 回填再学习。这是「智能体」与「工具」的分水岭。

GOVERN

治理护栏（15 表）

优化结果必须过 15 张判定表的领域约束，越界即报警交人审；同时作为解释模板与训练/评估基准。

三、五层架构

四、15 张判定表的重新定位

判定表是你的核心领域 IP，不该丢，但要降为治理层：

  • 护栏（Guardrail）：智能体优化结果必须过 15 张表的领域约束，越界即报警交人审。
  • 解释模板：把模型的"为什么"翻译成行业人话时，表是话术与逻辑来源。
  • 训练 / 评估基准：表 + 41 章教材 + 76 套真题，构成垂直领域的标注与评测集——这才是评审眼里的"AI 资产"。

五、MVP 真·智能体及格线

满足以下任意 3 条才算 AI，否则仍是 Excel：

  • ✅ 自动数据接入（免手填）
  • ✅ 有"学出来 / 优化出来"的非查表推荐
  • ✅ 自然语言推理 + 解释
  • ✅ 自主闭环 + 结果回填学习
  • ✅ 能处理 15 张表之外的状态

七、一人 OPC 落地路线（数据是大坎）

  1. 注册与入驻：在武汉光谷（东湖高新区）注册一人有限公司，入驻光谷数字文化 OPC 社区（免费场地 + 算力 + 陪跑），漫剧方向绿灯。
  2. 搭仿真沙盒：用教材数据 + 合成酒店数据，先做出"自动接入→预测→优化→解释→学习"可演示闭环，证明智能体跑得动。
  3. 单店试点：以一家合作酒店的真实数据跑闭环，拿到"实际提升收益"的证据——这是评审最看重的部分。
  4. 申领低门槛：算力服务券（50%、最高 20 万）、社区免费算力、创业担保贷（个人最高 30 万）、购房/租房补贴。
  5. 进阶评定：AI 人才创办 OPC 经评定最高 100 万、武汉英才 20–100 万、示范应用场景（总投入 30% 最高 100 万）、算力贷最高 1000 万。

最难一环是数据接入——需酒店开放系统或公开数据。打法优先级：仿真沙盒（零合作即可做）→ 单店试点（一家即可）→ 规模化。光谷 OPC 要的是"跑得动的 AI 产品证据"，仿真 + 单店试点已够起步。

八、智能体输入输出示例（节选）

场景：武汉某 300 间房商务酒店，周五（非会展周），距入住日 14 天。

  • 数据层自动拉取：同房型竞品 ADR ¥560、OTA 间夜占比 38%、历史同档取消率 12%、本地无大型活动。
  • 预测层：基于 booking curve 预测剩余 14 天散客需求 210 间夜，置信区间 [190, 235]；团队询单 60 间夜（待签约）。
  • 优化层：在最小连住 1、超售率上限 3% 约束下，求解散客基准 ADR ¥618、周五上浮至 ¥688、团队价 ¥540（低于散客 0.9 倍，符合判定表 R=团队价÷散客 ADR），预期 RevPAR +6.2%。
  • 推理层输出："建议周五散客 ADR 由 ¥618 调至 ¥688。依据：竞品上浮 + 周末需求弹性低；团队 60 间夜按 ¥540 接，因低于散客 0.9 倍且锁定确定收益。护栏检查：超售 3% 在判定表 H 允许区间，通过。"
  • 执行层：生成渠道调价单，推送 GM 确认后下发；若 48h 内取消率超 15% 自动回滚并告警。

注意：以上数值由智能体从实时数据算出，非查表所得——这正是与 Excel/判定表网页的本质区别。

十、技术栈与一人 OPC 可行性

智能体的五层均可由一人借助 AI 工具自建，无需大团队：

  • 数据层：Python + 轻量连接器（PMS/OTA 多为开放 API 或导出 CSV）；仿真阶段用合成酒店数据。
  • 预测层：scikit-learn / XGBoost 做需求与取消率预测，输出概率区间。
  • 优化层：OR-Tools / PuLP 做约束价格优化（超售、最小连住、渠道分配）。
  • 推理层：合规大模型 API 做自然语言解释与 what-if，RAG 检索教材与判定表。
  • 护栏层：15 张判定表转写为 Python 校验函数，优化结果必经其校验方可下发。
  • 执行层：定时任务 + 渠道管理 API / 企业微信告警，形成闭环。

关键在于：领域 know-how（判定表、教材、真题）是壁垒，工程可由一人 + AI 杠杆完成——这正是 OPC 形态成立的底层逻辑。
