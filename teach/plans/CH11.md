# 第 11 章 · 超额预订：卖出去的比有的多 教案

## 一、学完这一章，学生能做到什么

- 读完能算清：多卖几间是本事，多卖太多是事故。
- 为什么超售：总有取消和 No-show，不超售就等于白白空房。
- 超售是对"需求不确定性"的对冲。
- 超多少取决于历史与容忍度：看历史取消率、No-show 率，以及你能承受多大的 walk 风险。
- 超售不是越多越好：每多超一间，收益增量递减，而 walk 的成本陡增（赔偿 + 口碑）。

## 三、讲这一章要用的公式与定义

- **核心公式**：理论超售 = 可售房 × (预计取消率 + No-show 率) 实际超售 = 理论超售 − 安全缓冲（建议 3–5 间） walk 成本 = 安置他店房费 + 交通补偿 + 次日房费 + 口碑损失
- **算例 3 · 找最优超售点**：100 间房，取消+No-show 率 12% 超售 6 间 ：预计收益 +2,400，walk 概率 ~2% 超售 10 间：预计收益 +3,600，walk 概率 ~8% 超售 14 间：预计收益 +4,200，walk 概率 ~20%

## 四、讲这一章要用的判定表

### 本章判定表 · 超售额度怎么定

| 判据 | 结论 |
|---|---|
| 历史取消 + No-show 率 | 统计近 90 天，按星期几分别统计（周一与周五规律不同） |
| 是否旺季/紧俏日 | 紧俏日 → 降低超售甚至不超（walk 代价太高） |
| 房型是否可升级 | 有升级空间 → 可多超（walk 时升级解决）；无 → 少超 |
| 周边有无同档酒店 | 有 → 可多超（便于安置）；没有 → 少超 |
| 团队/协议客占比 | 占比高 → 少超（团队 No-show 率低且集中） |
| 是否做到店确认 | 已做（短信/电话确认）→ No-show 率下降，可少超 |
| 红线 | 预计 walk 率必须 ≤ 可接受阈值（通常 &lt;0.5%） |

### 场景：明天预计满房，100 间可售，需定超售额度

| 判据 | 结论 |
|---|---|
| 历史取消率（按星期几） | 该星期几历史取消 7% ✓ |
| 历史 No-show 率 | 4% → 合计 11% → 理论超 11 间 |
| 是否紧俏日？ | 预计满房 → 是 → 应减少超售 ✗ |
| 有升级空间吗？ | 有 5 间套房可升级 → 可适度多超 ✓ |
| 周边有同档酒店吗？ | 有 2 家 → 便于安置 ✓ |
| 团队占比？ | 团队占 30%（No-show 率低）→ 应少超 ✗ |
| 做了到店确认吗？ | 已发短信确认 → No-show 率可下调 ✓ |
| 最终额度 | 理论 11 − 缓冲 4 = 7 间；分房型：标准房 6、套房 0 |

### 遇到下面这些情况，直接按"动作"做

| 判据 | 结论 |
|---|---|
| 明天满房，超售几间 | 理论值 = 可售 ×(取消率+No-show率)，再减缓冲 3–5 间 |
| 紧俏日/满房日 | 减少超售甚至不超——walk 代价最高 |
| 套房要不要超售 | 通常不超（无法升级替代，walk 只能外送） |
| walk 频繁 | 先做到店确认（短信/电话），No-show 可降约三分之一 |
| 周边没有同档酒店 | 安置困难 → 少超 |
| 团队占比高 | 团队 No-show 率低 → 少超 |


## 五、课堂案例（直接用正文里的）

### 案例一 · 一次 walk 的真实代价

某店超售 12 间，当天 4 位客人被 walk。见上方算例 2。 直接赔付 4,400 元，加上 4 条差评对 OTA 评分的长期影响（评分每降 0.1，需降价约 2–5% 才能维持转化，见第 24 章）。 / 结论：walk 的代价远不止当晚的房费，它还包括长期的评分损失。

### 案例二 · 到店确认替代超售

某店原超售 10 间，walk 频发。后改为：入住前 1 天给全部预订客人发确认短信并电话确认团队。 No-show 率从 5% 降到 3%，超售额度随之降到 6 间，walk 几乎消失，而出租率未受影响。 / 结论：与其多超售，不如先把 No-show 降下来。到店确认是最便宜、最安全的手段。

### 案例三 · 分房型超售救了一次

某店统一超售 8 间。某日 8 位客人同时到店，其中 2 位订的是套房。 由于该店套房从不超售，这 2 位客人的房是真实存在的，顺利入住；其余 6 位标准房客人通过升级到行政房解决（有升级池）。 / 结果：零 walk。 / 结论：超售不是"总数"问题，是"结构"问题。分房型设置 + 留升级池，能把 walk 风险降到接近零。


## 六、容易讲错的地方

- 自学者提示：超售要配合"到店确认"——入住前 1 天给客人发确认短信或电话，能把 No-show 率砍掉约三分之一，比盲目多超售安全得多。这是最容易被忽略、也最有效的一个动作。

## 七、作业与测评

本章教材练习（答案在教材附录 B）：
- 算例 1：100 间房，历史取消率 8%、No-show 率 5%（合计 13%）。 / 理论超售 = 100 × 13% = 13 间。 / 减去安全缓冲 4 间 → 实际超 9 间。 / / 算例 2（walk 的代价）：某店超售 12 间，当天 4 位客人被 walk。房费 600，安置到同档酒店 800/间，另补偿交通与次日房费约 300/人。 / 赔付 ≈ 4 × (800 + 300) = 4,400 元，加上 4 条差评对 OTA 评分的长期影响。 / 而若不超售，当天会空 5 间，损失 5 × 600 = 3,000 元。 / 这一单超售是亏的——正确额度应降到 6–8 间。
- 从第 6 间到第 10 间：收益 +1,200，风险 +6 个百分点。 / 从第 10 间到第 14 间：收益仅 +600，风险 +12 个百分点。 / 结论：增量收益递减、风险递增 → 最优超售点通常在"理论值减半"附近（本例约 6–8 间）。
- 用法：超售必须分房型分别设——低价房型可多超（容易升级解决），套房、亲子房通常不超（无法替代）。填表示例 · 明天超售几间场景：明天预计满房，100 间可售，需定超售额度 历史取消率（按星期几）该星期几历史取消 7% ✓ 历史 No-show 率4% → 合计 11% → 理论超 11 间 是否紧俏日？预计满房 → 是 → 应减少超售 ✗ 有升级空间吗？有 5 间套房可升级 → 可适度多超 ✓ 周边有同档酒店吗？有 2 家 → 便于安置 ✓ 团队占比？团队占 30%（No-show 率低）→ 应少超 ✗ 做了到店确认吗？已发短信确认 → No-show 率可下调 ✓ 最终额度理论 11 − 缓
- 练习 100 间房，取消率 6%、No-show 4%，安全缓冲 4 间，求建议超售额度。 为什么紧俏日反而要少超售？ 除了赔偿，walk 还有哪些容易被忽略的成本？ 为什么超售要分房型分别设？ "到店确认"为什么能降低超售需求？ 本章小结（5 条，可复述） 超售是对"取消与 No-show"的对冲，不是投机。 公式：实际超售 = 可售房 ×（取消率+No-show 率）− 安全缓冲（3–5 间）。 边际递减：增量收益递减、walk 风险递增 → 最优点常在"理论值减半"附近。 分房型设置：低价房型可多超，套房通常不超（无法升级替代）。 walk 代价远超赔付：含评分下降带来的长期定价能力损失
