## 一、学完这一章，学生能做到什么

- 读完能搭出：一套不乱、不塌、谁都能执行的价格结构。
- BAR（最佳可用房价）：某一时刻公开可订的最低无限制价格。
- 其他价格围绕 BAR 打折或加价：会员价 = BAR × 0.9，协议价 = BAR × 0.85，套房 = BAR + 差价。
- BAR 是浮动的，价差结构是固定的：BAR 每天变，但各档与 BAR 的比例关系保持稳定——这就是"体系"二字的含义。

## 三、讲这一章要用的公式与定义

- **核心结构**：BAR（最佳可用房价）= 公开可订的最低无限制价 会员价 = BAR × 0.90 ~ 0.95 协议价 = BAR × 0.80 ~ 0.90（需资质证明） 团队价 = 按置换分析单独议（第 15 章） 套餐价 = 房价 + 附加项，且不可低于 BAR 拆算值（第 8 章）
- **算例 3 · 一次 BAR 调整的全体系联动**：BAR 600 → 700（+16.7%） 会员价 0.92×：552 → 644 协议价 0.85×：510 → 595 团队价 ：按置换另议 行政房 1.25×：750 → 875 套餐价 ：780 → 880（保持高于 BAR）

## 四、讲这一章要用的判定表

### 本章判定表 · 价格体系是否健康（七项自查）

| 判据 | 结论 |
|---|---|
| BAR 是否唯一 | 同一时刻只能有一个 BAR；多个最低价 = 体系已乱 |
| 各渠道价格是否一致 | 同档同房型，各渠道价格应一致（差异来自权益，不是裸价） |
| 协议价是否失控 | 协议客占比过高、或协议价低于 BAR 太多 → 需重谈 |
| 是否存在现场放价 | 前台能否不经审批改价？能 → 体系有漏洞（第一大漏洞） |
| 公开价是否高于协议/会员价 | 是 → 违反公平性，会引发投诉（红线） |
| 价差结构是否稳定 | 各档与 BAR 的比例应固定，不应每天随意变 |
| 年审 | 价格体系每年重审一次，季度只做微调 |

### 场景：以普通客人身份在同一天查三个渠道

| 判据 | 结论 |
|---|---|
| 官网同房型价格 | 680 |
| OTA A 同房型价格 | 668（低于官网）→ ✗ |
| OTA B 同房型价格 | 680 ✓ |
| 差异原因 | OTA A 参与了平台补贴活动，未报备 |
| 风险 | ① 客人比价后不满 ② 直销被自己打压 ③ BAR 出现两个 |
| 动作 | 立即与 OTA A 核对，取消未报备补贴或同步调整官网权益 |
| 机制 | 建立"每月一次神秘顾客检查"并留档 |

### 遇到下面这些情况，直接按"动作"做

| 判据 | 结论 |
|---|---|
| 价格档位越来越多 | 定期清理：先停用零使用档（最省力），再把遗留档改"需审批" |
| 客人在别处看到更低价 | 查是否未报备的渠道补贴 → 立即核对并同步 |
| 前台能否现场改价 | 收权 + 快速审批通道（30 秒）；投诉通常不会上升 |
| 每天要调十几个价档 | 说明没有体系 → 只调 BAR，其余按比例联动 |
| 不知道体系是否健康 | 每月做神秘顾客检查（官网/OTA/小程序三处同查） |


## 五、课堂案例（直接用正文里的）

### 案例 · 价格体系治理带来的收益

某店有 17 种价，前台可现场放价。诊断后发现：协议价占比 40%，且平均低于 BAR 35%。 动作：① 砍掉冗余价档，只保留 5 档；② 协议价统一重谈，控制在 BAR 的 80–88%；③ 关闭前台改价权限，改价需走流程。 / 结果：ADR 提升 12%，而出租率基本不变。 / 这是"不降价也能提升收入"的典型——收益管理最大的漏损往往在价格体系治理，不在每日调价。

### 案例三 · 收回前台改价权

某店前台可自行给客人降价（最多 20%）。店长认为这是"灵活服务"。 数据核查发现：前台改价的订单中，约 70% 的客人并未主动要求折扣——是前台为"促成成交"主动让利。 / 改为"改价需收益岗审批（可电话、30 秒内响应）"后，改价订单减少 72%，ADR 提升 5.4%，而投诉率没有上升。 / 结论：现场放价多数不是客人要的，是员工怕麻烦。收回权限 + 快速审批通道，两头都解决了。

### 案例四 · 清理价档的完整过程

某店从 17 档价清理到 5 档，历时两个月： / 第 1 周：列出全部 17 档，逐档标注"谁在用、用了多少、是否经审批"。 / 第 2 周：发现 6 档近一年零使用 → 直接停用（最轻松的一步）。 / 第 3–4 周：5 档为"历史遗留"（大客户价、活动价、总经理特批价）→ 不删除，改为"需审批"，权限收回系统。 / 第 5–6 周：剩余 6 档合并同类项 → 保留 BAR / 会员 / 协议 / 团队 / 套餐 5 档。 / 第 7–8 周：关闭前台自由改价权限，改为"电话审批 + 30 秒响应"。 三个月后统计：历史遗留档使用量下降 78%；前台改价订单下降 72%；ADR 提升 5.4%，投诉率未上升。 / 结论：清理价档的最大发现，往往是"大部分价档根本没人用，只是挂在菜单里制造混乱"。先停用零使用档，成本最低、阻力最小。


## 六、容易讲错的地方

- 自学者提示：检验价格体系是否健康，最简单的方法：以普通客人身份，在同一天查官网、OTA、小程序三个渠道的同房型价格。若三者不同，体系已乱——而这通常是收益管理失效的真正原因，不是"不会调价"。

## 七、作业与测评

本章教材练习（答案在教材附录 B）：
- 算例：某日 BAR = 600。 / 会员价 540、协议价 510、团队价另议、行政房 750。 / 次日需求变强，BAR 提到 700 → 会员 630、协议 595、行政 875。 / 只动 BAR，其余按比例自动跟随——这就是体系的价值：一天只需改一个数，而不是十七个数。
- 只改 BAR 一个数，五档价格同步联动。 / 若没有体系，调价要逐档重算，既慢又容易出错——这正是"价格体系"存在的意义：让每天的调价变得可执行。
- 用法：每月做一次"神秘顾客"检查：以普通客人身份查官网、OTA、小程序三个渠道的同房型价格。三者不同，体系已乱。填表示例 · 神秘顾客检查场景：以普通客人身份在同一天查三个渠道 官网同房型价格680 OTA A 同房型价格668（低于官网）→ ✗ OTA B 同房型价格680 ✓ 差异原因OTA A 参与了平台补贴活动，未报备 风险① 客人比价后不满 ② 直销被自己打压 ③ BAR 出现两个 动作立即与 OTA A 核对，取消未报备补贴或同步调整官网权益 机制建立"每月一次神秘顾客检查"并留档 结论：渠道价差必须源于"权益差异"，不能源于"裸价差异"。 / 任何未报备的渠道补贴，都是对价格体系
- 练习 BAR=580，设计会员价、协议价、行政房价（给出比例与理由）。 为什么"同一时刻只能有一个 BAR"？ 为什么公开价不能高于协议价？ 某店有 17 种价格，可能存在哪些问题？如何治理？ 为什么"前台现场放价"是价格体系第一大漏洞？ 本章小结（5 条，可复述） BAR＝公开可订的最低无限制价；同一时刻只能有一个。 其他价围绕 BAR：会员 0.90–0.95、协议 0.80–0.90、套房 +20–30%。 BAR 浮动、比例固定——一天只改一个数，全体系自动联动。 渠道价差应源于权益，不是裸价；未报备补贴是对体系的破坏。 前台自由改价是最大漏洞；收回权限 + 快速审批可两头兼顾。
