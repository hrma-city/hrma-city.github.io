## 一、学完这一章，学生能做到什么

- 读完能判断：什么时候该上系统，没系统时怎么办。
- 系统做三件事：自动取数、自动预测、自动建议价格。
- 上系统的前提是数据干净：历史数据、渠道成本、取消率必须准确，否则" garbage in, garbage out"。
- 没有系统也能做：Excel + 判定表可以覆盖 80% 的动作，且更可控。

## 三、讲这一章要用的公式与定义

- **核心判据（上系统的四个前提）**：① 房量 &gt;80~100 间 ② 有 2 年以上干净历史数据 ③ 有专人负责（哪怕兼职） ④ 已有稳定的手工流程 四条不全中 → 先用 Excel + 判定表
- **算例 · 上系统的投入产出**：RMS 年费 6 万 + 实施 3 万 + 学习成本（约 80 小时） 收益：每日省 30 分钟 → 年省约 180 小时 预测准确度提升带来的收益：视规模而定 盈亏平衡：需年增收 &gt; 9 万 + 学习成本

## 四、讲这一章要用的判定表

### 本章判定表 · 系统怎么用才有效

| 判据 | 结论 |
|---|---|
| 数据是否干净 | 历史数据、渠道净价、取消率准确 → 可上；否则先治理数据 |
| 有没有人负责 | 有专职/明确兼职 → 可上；无人 → 不上 |
| 手工流程是否已跑通 | 已跑通 → 系统接管；未跑通 → 先跑通 |
| 是否盲目信任建议价 | 系统建议必须过判定表复核，不能直接执行 |
| 是否有留痕 | 系统外也要记录"为什么不采纳系统建议" |
| 房量门槛 | &lt;80 间的酒店，手工 + Excel 通常更高效 |
| 常见失败 | 买了系统但流程没改 → 系统变成昂贵的报表工具 |

### 场景：RMS 销售来提案，如何评估

| 判据 | 结论 |
|---|---|
| 我房量够吗？ | 100 间 → ✓（&lt;80 间则应慎重） |
| 历史数据干净吗？ | 近 2 年数据完整、口径统一 → ✓；否则先治理 ✗ |
| 有专人负责吗？ | 有兼职收益岗 → △（需明确时间投入） |
| 手工流程跑通了吗？ | 已用 Excel 跑 3 个月 → ✓（最关键的一条） |
| 能接入历史数据吗？ | 销售确认可导入 → ✓ |
| 建议能复核吗？ | 可导出建议与依据 → ✓（便于过判定表） |
| 能记录不采纳原因吗？ | 有备注字段 → ✓ |

### 遇到下面这些情况，直接按"动作"做

| 判据 | 结论 |
|---|---|
| 销售说"不上系统做不了" | 不对——Excel + 判定表可覆盖 80% 决策 |
| 上了系统没人用 | 多半是流程没先跑通 → 先用 Excel 跑满 3 个月 |
| 系统建议与判定表冲突 | 听判定表，并记录冲突（往往是系统参数需调整的信号） |
| 要不要买系统 | 四前提：房量&gt;80、数据干净、有专人、手工流程已跑通 |
| 竞品新开业 | 系统看历史、人看变化 → 必须人工复核 |


## 五、课堂案例（直接用正文里的）

### 案例 · Excel 打赢了系统

A 店上 RMS 后按建议价执行，一年后 RevPAR 持平。B 店用 Excel + 判定表，每日 20 分钟人工复核。 差别在于：B 店每次调价都对照判定表，并记录了"为什么"；A 店直接采纳建议，遇到系统预测偏差时毫无察觉。 / 结论：系统的价值在于"算得快"，判据的价值在于"算得对"。没有判据，系统只是更快地做错决定。

### 案例三 · 系统发现不了的事

某店上了 RMS 后一切照建议执行。某月竞品新开业，系统按历史数据仍建议提价。 结果提价后 pickup 骤降，当月 RevPAR 落后市场 9%。 / 而另一家用 Excel 的店，因为每周手工看竞品价格，提前发现了新竞品并做了应对。 / 结论：系统看历史，人看变化。竞品新开业、政策变动、突发事件——这些系统往往滞后，必须靠人复核。

### 案例四 · 一次系统选型的对比

某 120 间房酒店评估两套方案： / 方案 A（RMS 系统）：年费 6 万 + 实施 3 万；自动取数、自动预测、自动建议；需 80 小时学习。 / 方案 B（Excel + 判定表）：零费用；需人工取数（每天 20 分钟）、手工预测（按星期几 + 提前期）；已跑通 6 个月。 该店的判断： / · 有专职收益岗（每天可投入 1.5 小时）→ 系统省下的时间可被有效使用 ✓ / · 历史数据 3 年、口径统一 ✓ / · 手工流程已跑通 → 知道要自动化什么 ✓ / 结论：选 A，但先用 Excel 再跑 3 个月，把流程彻底固化后再切换。 / 方法论：不是"要不要上系统"，而是"我现在上，能不能把它的价值用满"。用不满就先不上——Excel 不会成为瓶颈，混乱的流程才会。


## 六、容易讲错的地方

- 自学者提示：先用 Excel 建你的"晨间 15 分钟表"（第 23 章），跑满 3 个月。那时你会很清楚自己需要系统的哪些功能——再采购就不会被销售牵着走。

## 七、作业与测评

本章教材练习（答案在教材附录 B）：
- 算例：60 间房的单体酒店，无专职收益岗。 / 上 RMS：年费数万，但无人维护 → 大概率闲置。 / 替代方案：一张 Excel（在手/pickup/竞品/预测）+ 一套判定表 + 每周 30 分钟 → 能覆盖主要决策。 / 结论：先用手工跑通流程，再让系统接管——顺序反了必然失败。
- 对 60 间房、无专职收益岗的酒店：省下的 180 小时无人承接，预测改善有限 → 大概率不划算。 / 对 150 间房、有专职收益岗的酒店：省下的时间可用于策略工作，预测改善明显 → 通常划算。 / 结论：系统值不值，取决于"省下的时间有没有人用、用在哪"。
- 用法：采购前先问自己：我的手工流程跑通了吗？没跑通就买系统，只会把混乱自动化。填表示例 · 采购前先答这七项场景：RMS 销售来提案，如何评估 我房量够吗？100 间 → ✓（&lt;80 间则应慎重） 历史数据干净吗？近 2 年数据完整、口径统一 → ✓；否则先治理 ✗ 有专人负责吗？有兼职收益岗 → △（需明确时间投入） 手工流程跑通了吗？已用 Excel 跑 3 个月 → ✓（最关键的一条） 能接入历史数据吗？销售确认可导入 → ✓ 建议能复核吗？可导出建议与依据 → ✓（便于过判定表） 能记录不采纳原因吗？有备注字段 → ✓ 结论：七项中"手工流程已跑通"最关键。 / 没跑通就上系统，
- 练习 上 RMS 的四个前提条件是什么？ 为什么"先用手工跑通，再上系统"？ 系统建议价为什么必须过判定表复核？ 60 间房、无专职收益岗的酒店，应该上系统吗？ 系统上线后最常见的失败模式是什么？ 本章小结（5 条，可复述） 系统是放大器：方法对，它放大对；方法错，它放大错。 四个前提：房量 &gt;80、2 年以上干净数据、有专人负责、手工流程已跑通。 先跑通手工流程——否则会把混乱自动化。 建议价必须过判定表；系统看历史，人看变化（新竞品、政策）。 值不值取决于"省下的时间用在哪"——没人承接，就不划算。
