## 一、学完这一章，学生能做到什么

- 读完能回答：凭什么现在就知道那天会不会满房。
- 预测的对象是需求曲线，不是最终出租率：你要猜的是"每天会来多少订单"，而不是"月底能住满多少"。
- pickup（预订进度）是预测的最小单元：每个提前期新增多少预订，是可以直接统计的历史规律。
- 预测要不断修正：把预测值和实际 pickup 对比，偏差就是下次的修正依据。

## 三、讲这一章要用的公式与定义

- **核心公式**：某日最终预订量预测 = 当前在手 + Σ(剩余各提前期的历史 pickup) pickup(提前期 d) = 历史上「距入住 d 天」那天新增的预订数 预测准确度：MAPE（平均绝对百分比误差）&lt;10% 为良好
- **算例 3 · 预测随时间的自我修正**：D-10：在手 50，历史剩余 pickup 35 → 预测最终 85 D-7 ：在手 63（实际新增 13，历史为 11）→ 略快 剩余 pickup 修正为 26 → 预测最终 89 D-3 ：在手 78（新增快于历史）→ 预测最终 94 D-1 ：在手 91 → 预测最终 93（收敛）

## 四、讲这一章要用的判定表

### 本章判定表 · 预测与需求日历怎么用

| 判据 | 结论 |
|---|---|
| 用多久的历史 | 至少 2 年，剔除异常年（如疫情、大修、政策突变） |
| 按什么分组 | 按星期几分组（周一与周六 pickup 完全不同）；再叠加事件日 |
| 偏差怎么看 | 实际 pickup 持续高于预测 → 上调；持续低于 → 下调 |
| 日历标什么 | 展会、演出、赛事、节假日、寒暑假、考试季、航班换季 |
| 日历更新频率 | 每周一更新，滚动往后补 7 天（固定动作） |
| 事件日提前量 | 大型事件提前 6–12 个月标注并开始布价 |
| 准确度标准 | MAPE &lt;10% 为良好；&gt;20% 需重建模型 |
| 最重要的用途 | 预测决定保护位（第 12 章）——预测越准，收益越高 |

### 场景：距入住 6 天，预测最终 88 间，但近 3 天实际 pickup 明显偏慢

| 判据 | 结论 |
|---|---|
| 预测值 | 88 间（可售 100，预计出租率 88%） |
| 实际 pickup | 近 3 天日均 5 间，历史同期 9 间 → 明显偏慢 |
| 是日历事件变化吗？ | 查日历：原标注的展会取消 → 是原因之一 |
| 是渠道异常吗？ | 查渠道：某 OTA 配额已满，关闭了 → 是原因之二 |
| 修正预测 | 下调至约 76 间 |
| 对应动作 | 释放保护位、开放低价档填量（不硬守） |
| 记录 | 写明"展会取消 + OTA 配额满"两个原因，供下次参考 |

### 遇到下面这些情况，直接按"动作"做

| 判据 | 结论 |
|---|---|
| "在手很低，是不是很淡" | 不一定——看pickup 是否还没启动（参考去年同期的增长节奏） |
| 要不要现在降价 | 先查历史：增长发生在哪个提前期；别动手太早 |
| 预测偏差很大 | 先查原因（事件取消？渠道关闭？），再修正动作 |
| 没有预测系统 | 用 Excel：行=星期几，列=提前期，填历史 pickup |
| 不知道有什么活动 | 建信息源清单：展馆、票务、校历、航线公告 |
| MAPE &gt; 20% | 预测模型需重建（先查口径与异常年） |


## 五、课堂案例（直接用正文里的）

### 案例 · 两次不同的"感觉"

A 店凭经验判断展会日"肯定满"，提前 30 天关掉所有低价档。B 店查历史：去年同展会 D-30 在手只有 30 间，最终 95 间。 B 店判断：增长空间还很大，此时关闭低价档为时过早，应先保持开放、观察 pickup。 / 最终 A 店因过早关档损失了大量中价客源；B 店逐步收紧，满房且均价更高。 / 结论：预测的价值在于"什么时候该动手"，而不只是"会不会满"。

### 案例三 · 一张日历的复利

某店第一年只标了 8 个事件日（主要是法定假期）。第三年，他们建立了完整的信息源，标出了 31 个。 第三年事件日带来的额外收入是第一年的 3.6 倍，而投入几乎没变（每月 30 分钟信息同步）。 / 结论：需求日历是有复利的资产——第一年粗糙，第三年精准，而它每年都在自动产生收益。

### 案例四 · 预测如何救了一次布价

某店 D-21 时的一场争论： / 销售："展会还有三周，在手才 30 间，肯定很淡，要不要先降点价？" / 收益："我查了去年同展会：D-21 在手 28 间，最终 95 间。增长主要发生在 D-10 到 D-2。" / 销售："所以现在不能降？" / 收益："对。现在在手低是正常的——因为散客还没开始订。如果现在降价，就是把后面会来的高价客提前贱卖了。" / 销售："那什么时候动手？" / 收益："等到 D-10，看 pickup 是否如期启动。启动了就收紧，没启动再促销也不迟。" D-10 时 pickup 果然启动（日均 12 间，历史 5 间），该店按计划收紧低价档并分阶段提价，最终满房且 ADR 比去年高 18%。 / 结论：预测的价值不只是"算出结果"，更在于"告诉你现在该不该动手"。很多错误不是判断错，是动手太早。


## 六、容易讲错的地方

- 自学者提示：没有系统也能做预测——用 Excel 建一张表：行是星期几，列是提前期（D-30 到 D-0），填入历史 pickup，就是你的第一个预测模型。 / 再单独建一张"需求日历"，把明年本地的展会、演出、假期标进去。这两张表，就是整个运营篇的地基。

## 七、作业与测评

本章教材练习（答案在教材附录 B）：
- 算例：距某日还有 10 天，当前在手 50 间。 / 历史 pickup：D-10 新增 4、D-9 增 5、D-8 增 3……D-1 增 2，剩余期合计约 35 间。 / 预测最终 = 50 + 35 = 85 间。可售 100 间 → 预计出租率 85%，属紧俏 → 可执行保护位与关低价档。 / 关键：随着时间推进，用实际 pickup 替换历史值，预测会自动收敛变准。
- 预测会随实际数据不断收敛，越临近越准。 / 这正是"每天用实际替换历史"的意义——预测不是一次算完就放着，而是每天在更新。 / 若某天实际 pickup 明显偏离，就是需要人工干预的信号（检查是否有事件变化或渠道异常）。
- 用法：预测与日历是"一个定性、一个定量"：日历告诉你哪天特殊，pickup 告诉你实际来了多少。两者配合才是完整预测。填表示例 · 这个预测准不准、要不要干预场景：距入住 6 天，预测最终 88 间，但近 3 天实际 pickup 明显偏慢 预测值88 间（可售 100，预计出租率 88%） 实际 pickup近 3 天日均 5 间，历史同期 9 间 → 明显偏慢 是日历事件变化吗？查日历：原标注的展会取消 → 是原因之一 是渠道异常吗？查渠道：某 OTA 配额已满，关闭了 → 是原因之二 修正预测下调至约 76 间 对应动作释放保护位、开放低价档填量（不硬守） 记录写明"展会取消 + OTA
- 练习 当前在手 60，剩余提前期历史 pickup 合计 25，预测最终多少间？ 为什么预测要按星期几分组？ 实际 pickup 连续一周高于预测，说明什么、该怎么办？ MAPE 大于 20% 说明什么？ 需求日历应标注哪些事件？至少列出 5 类。 本章小结（5 条，可复述） 预测对象是需求曲线，不是最终出租率。 pickup 是最小单元：统计每个提前期的历史新增量。 预测 = 当前在手 + 剩余各期的历史 pickup，并每天用实际值替换历史值。 日历是定性、pickup 是定量：日历说"哪天特殊"，pickup 说"实际来了多少"。 偏差要查原因：事件取消？渠道关闭？——偏差本身就是信号。
