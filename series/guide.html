使用说明

这本手册怎么用

如果你没时间系统地学一门学问，只想明天就能用——翻这本就够了。

全书不按学科体系排，按你工作的节奏排：每天做什么、遇到场景怎么判断、每周每月开什么会、最后一张自查清单。

第一部分

每日动作：早上九点的十五分钟

看五个数（2 分钟）
今天的在手预订、昨天的 pickup、昨天与去年同期的 RevPAR、竞争群今天的挂牌价、今天是否有特殊事件。
做一次判断（5 分钟）
未来三天是不是马上要满？pacing 是领先还是落后？竞争群有没有异动？
动一次价格或库存（8 分钟）
每次只做一个动作：上调、下调、关闭某个房型、或什么都不做。做完必须记录。
每日判断树
今天或明天预计入住率 ≥ 90%？ 是 → 检查是否该提价 / 该上限制 否 → 检查 pacing 是否落后去年同期 落后 → 先查渠道与点评，再谈降价 领先 → 保持或小幅试探上调
最常见的错误：每天因为“感觉”反复小幅调价。没触发就不要动，频繁改动会让你的历史数据失去参考价值。
第二部分

场景决策：碰到什么情况怎么做

以下 32 个卡片覆盖日常工作的主要场景。每张卡一句话给结论，需要细节时翻对应的口袋书。

百分之九十二的入住率，输给了百分之七十八

结论：一句话讲清：为什么你天天满房，却不如隔壁没住满的店赚钱
马上做：从今天起每天开盘先看 RevPAR，而不是先看入住率。花五分钟算昨天的数，比盯一上午前台有用。
跟着做：找出你店里“最容易满、却卖得最便宜”的那个房型——它通常就是你最大的漏点。
不要做：为了追求满房一路降到底价　/　只看今天的出租率就下结论　/　在还没算清 RevPAR 之前就动手调价
算法：RevPAR = 入住率 × 平均房价　→　详见口袋书 No.01

同一个人同一个店，算出了三个不同的平均房价

结论：把这三个数真正看懂，你才有资格跟任何人谈价格
马上做：今天就把全店统一的口径表写出来：免费房、自用房、超售、升级各怎么算，签字贴前台。
跟着做：把三个数做成一张老板看得懂的日报：今天 / 昨天 / 去年同期三列对比。
不要做：用不同口径的数互相比较　/　拿单一指标下商业决策　/　把 RevPAR 当成净收益
算法：OCC = 已售房晚 ÷ 可售房晚　→　详见口袋书 No.02

老板问：“我们到底算贵还是算便宜？”

结论：不用打听底价，也能知道自己在市场里到底是贵了、还是没份额
马上做：今天就定死你的竞争群：写名字、写档次、写为什么要对比它，不要随便换。
跟着做：每天同一时间记录一次竞争群的挂牌价，做成一张雷打不动的表格——这是你最值钱的数据资产。
不要做：只看 ARI 就决定是否涨价　/　把不同档次竞争对手混在一起来平均　/　用一天的汇率数据做月度判断
算法：MPI = 本店入住率 ÷ 竞争群入住率　→　详见口袋书 No.03

“一提价就没人订了”——这句话很少是真的

结论：给你一个敢涨价的理由，和一条不该越过的红线
马上做：先分需求等级：把未来 30 天按入住率分成高、中、低三档，只在高档日子试探涨价。
跟着做：单次调幅控制在 5%–8%，观察三天的预订速度（pickup）再决定要不要加码。
不要做：一次性跳涨超过 12%　/　在淡季照搬旺季的涨价幅度　/　不看 pickup 就连续加价
算法：新需求量 = 原需求量 × (1 + E × 价格变动%)　→　详见口袋书 No.04

每天问自己该不该涨，是最消耗人的活

结论：五个可以挂在墙上的触发条件，让你不必再靠直觉拍脑袋
马上做：把五条触发条件打印出来贴在工位，从明天起只按清单决策。
跟着做：对每个即将到来的高需求日，提前 20 天开始记每天的 pickup。
不要做：在同一个房型上一次跳涨超过 10%　/　在没有任何触发条件时因为“感觉该涨”而调价　/　调完不看 pickup 就连续加码
算法：pickup（当日新增）= 今日在手预订 − 昨日在手预订　→　详见口袋书 No.05

一边空着 24 间，一边把客人送去了别家

结论：给超售一个能向店总交代的算法，和一份万一出事的处理流程
马上做：把过去六个月每天的取消数和 No-show 数拉出来，算自己店的平均未到率。
跟着做：只在系统预测入住率 ≥ 95% 的日子开启超售，且数量由公式给出，不由心情给出。
不要做：在没有退路的日子超售　/　把超售当成常规手段全年开启　/　让一线员工自行决定要不要超售
算法：推荐超售数 = 预计最终需求 × 历史 No-show 率 × 保守系数　→　详见口袋书 No.06

三个房型只差 20 元，客人为何该选贵的

结论：不靠店员推销，让客人在对比中自己选择更贵的那一间
马上做：把自己店所有房型列一行，算出每对相邻房型的价差率，找出低于 8% 的那几对。
跟着做：给每一个价差写一句“为什么值这个钱”，写不出来的差价就该重新设计。
不要做：把看不见的差异算进房价　/　让所有房型挤在 5% 以内的价差里　/　用口头推销替代明码栅栏
算法：相邻房型价差率 = (高一档房价 − 低一档房价) ÷ 低一档房价　→　详见口袋书 No.07

周六全满，周日空一半

结论：在旺季守住收益的最后一道闸门，以及它的三个禁用场合
马上做：找出未来 60 天里“目标日高需求、次日低需求”的那些日期，列一张清单。
跟着做：先对这些日子单独提价 5%–8%，三天后看效果再决定是否叠加 MinLOS。
不要做：全年无差别开启限制　/　官网与 OTA 设置不一致　/　设了限制之后忘记复查和解除
算法：触发：目标日预计入住率 ≥ 90%，且次日预计入住率低于其 15 个百分点以上　→　详见口袋书 No.08

月报表上说平均房价 420，财务说没钱赚

结论：同一间房卖 400 元，不同渠道到你口袋里差的钱能超过一百
马上做：把本店所有渠道列一张表，写出各自的佣金、返现、结算条件，算出净值。
跟着做：按净值排序而不是按订单量排序，重新看一遍你的渠道策略。
不要做：只看平均房价就做渠道决策　/　为了冲订单量把库存全压到高佣金渠道　/　忽略退订率差异
算法：渠道净值 = 挂牌价 × (1 − 佣金率) − 返现/积分 − 单笔其他成本　→　详见口袋书 No.09

同一个人的两次预测，一次很准一次离谱

结论：不用复杂模型，用一张去年的对照表就能判断今年是领先还是掉队
马上做：选定一个典型月份，把每个入住日的手预订曲线画出来，先只做一个月。
跟着做：每天早上花五分钟，把今日在手和去年同期同日在手两个数字记进表。
不要做：拿不同星期属性的日子做对比　/　在落后时第一时间降价　/　只看某一天的数据就推翻判断
算法：pickup（当日新增）= 今日在手 − 昨日在手　→　详见口袋书 No.10

对面掉了三十块，全店立刻炸了锅

结论：一套不必慌的判断顺序，和一条能保住房价体系的底线
马上做：遇到降价先走四步判断顺序，把结论写下来再动手，不当场做决定。
跟着做：准备三种“加值武器”：赠送早餐、房型升级券、会员积分，随时可置换 20–30 元的价格差。
不要做：看到对手降价就全线跟进　/　和市场里最低的那家比价格　/　降价之后不设回归日期
算法：不跟的预估损失 = 预计流失间夜 × 渠道净值　→　详见口袋书 No.11

接了个六十间的大团队，月底利润反而少了

结论：一个能当场算出盈亏线的置换公式，让你不必再靠“要不要做这一单”赌运气
马上做：先查目标日的散客需求预测与预计入住率——这是全部测算的前提。
跟着做：用上面的公式算出这一单的最低可接受价，写进报价前的审批表。
不要做：在没算置换成本前答应报价　/　只比平均房价、不比净收入　/　忽略团队更高的取消与缩房风险
算法：置换成本 = 被替代的散客间夜 × 散客渠道净值　→　详见口袋书 No.12

客人拿着手机问前台：为什么网上更便宜

结论：一个基准价管住几十种卖价，从此不再出现“同一个房五个价”
马上做：今天就写下本店的价格层级表：挂牌价、BAR、以及每一种派生价的比例与适用条件。
跟着做：把所有渠道的当日 BAR 拉出来对齐一次，找出不一致的地方。
不要做：让同一个房型在不同渠道出现不同基准价　/　用口头特价绕开规则　/　设了折扣规则却不设有效期
算法：折扣率 = 1 − 折后价 ÷ BAR　→　详见口袋书 No.13

同样的房，商务客和度假客愿意付的钱完全不同

结论：不再对所有客人报同一个价，而是给不同客人不同的门
马上做：列出本店现有的细分清单，写出每一类的提前期、取消率、价格敏感度三个特征。
跟着做：给每一个低价细分补上至少一条栅栏（不可取消 / 提前天数 / 最少住期）。
不要做：只按客人身份而不按行为细分　/　给低价细分却不设任何栅栏　/　分了细分却从不按细分统计
算法：某细分贡献度 = 该细分间夜占比 × 该细分渠道净值　→　详见口袋书 No.14

房还没到周末，就被最便宜的渠道订光了

结论：旺季不把好房间便宜卖光的一整套留房规则
马上做：给每个渠道写明每日配额上限，并写进渠道合同或后台设置。
跟着做：建立“临近回收”动作：D-7 收紧、D-3 回收，写进每周固定动作。
不要做：旺季把所有库存一次性放给所有渠道　/　只控价格不控库存　/　设了配额却从不回收
算法：低净值渠道配额 = 可售房 × 该渠道策略占比（旺季建议 20%–30%）　→　详见口袋书 No.15

每天重新想一遍“今天该涨还是该降”，是最耗神的活

结论：一张三色日历，把你从每天重新判断一次里解放出来
马上做：今天就给未来 90 天标一次颜色，并写明每一档对应的预设动作。
跟着做：固定每周一上午更新一次日历，滚动往后补 7 天。
不要做：按星期几凭经验涂色　/　标了颜色却不绑定动作　/　画一次之后三个月不更新
算法：红色：预计入住率 ≥ 90%　→　详见口袋书 No.16

“今年 RevPAR 做到 300”——然后呢

结论：把老板给的一个年度数字，拆成每天该卖多少钱
马上做：把过去三年的月度 RevPAR 拉出来，算出十二个月的月指数表。
跟着做：用年度目标乘月指数，得到每个月的目标，再拆到周。
不要做：把年度目标平均分成十二份　/　用单一年份数据算指数　/　年底才发现没完成
算法：月指数 = 该月历史 RevPAR ÷ 全年月均 RevPAR　→　详见口袋书 No.17

做了十几张表，老板还是说看不懂

结论：四类报表定死字段，老板只需要看一页纸
马上做：今天就砍掉一半现有报表，只留四类，每类一页。
跟着做：给每张表加一个结论栏，强制自己写一句人话。
不要做：为了显得专业堆砌字段　/　只给数据不给结论　/　报表发送时间随心情
算法：目标完成率 = 本期实际 RevPAR ÷ 本期目标 RevPAR × 100%　→　详见口袋书 No.18

招了个收益经理，半年后他还在做报表

结论：把岗位职责、考核指标与跨部门边界一次说清楚
马上做：今天就写一张授权表：收益经理能自己定什么、什么必须上报。
跟着做：把考核指标改成 RevPAR 达成率 + RGI + 预测准确率三项。
不要做：只给报表权不给决策权　/　用营业收入考核收益岗　/　收益策略只在一个部门内部流转
算法：自主调价区间：建议在 BAR 的 ±10% 以内　→　详见口袋书 No.19

一次促销做完，房价三个月没抬回来

结论：打折不是认输，但它必须有门槛、有期限、有止损线
马上做：给本店列出可动用的三种加值武器，并算出每一种的实际成本。
跟着做：任何促销必须写明：门槛、截止日、止损线，三项缺一不执行。
不要做：做没有截止日的促销　/　全线无门槛打折　/　降价却不设止损线
算法：保本销量 = 原价间夜 × 原价净值 ÷ 折后净值　→　详见口袋书 No.20

每年付出去的佣金，够再开一家分店的前厅

结论：算清一笔账：直销占比每提高一个点，你到底省下多少佣金
马上做：算出本店去年的佣金总额——先把这个数字摆在老板面前。
跟着做：设计一款只有直销才有的权益（建议：免费升级或延迟退房），成本可控且感知强。
不要做：用比 OTA 更低的裸价做直销　/　只算第一次入住的账　/　忽略前台这个最低成本的直销触点
算法：转移收益 = 转移间夜 × 平均房价 × (OTA 佣金率 − 直销获客成本率)　→　详见口袋书 No.21

参加了一堆活动，订单却没有涨

结论：把曝光、转化、点评三件事串起来，做对顺序别做反
马上做：先看自己的转化率，而不是先看曝光量——如果转化率低于同类均值，先修转化。
跟着做：统计近三个月差评，按责任部门归类，找出最高频的三类问题。
不要做：转化没修好就猛投曝光　/　只回复差评不归因　/　把房型详情页写成千篇一律
算法：订单量 = 曝光量 × 点击率 × 转化率　→　详见口袋书 No.22

平均房价涨了，利润却没动

结论：卖得贵不等于赚得多——往下算一层，才知道哪一单真正在赚钱
马上做：今天就向财务要一个数：每间房的变动成本是多少，含不含早餐。
跟着做：用变动成本重算一遍你现有的主要细分，看谁的边际贡献最高。
不要做：用营业收入代替利润做判断　/　不知道变动成本就谈折扣　/　认为低价单一定不值得接
算法：边际贡献 = 净房价 − 变动成本　→　详见口袋书 No.23

客人说贵，其实是在说“看不出值不值”

结论：不加价格也能提高客单价的三套组合方法
马上做：挑一个主销房型，设计一个含两项附加的套餐，并算出它的净收益。
跟着做：在房型陈列中明确标出“推荐档”，放在中间偏上位置。
不要做：用打包的名义做裸降价　/　套餐附加项成本不核算　/　把最贵档设为默认推荐
算法：套餐净收益 = 套餐售价 − 房晚固定成本分摊 − 各附加项变动成本　→　详见口袋书 No.24

旺季涨价总是慢半拍

结论：把一年的涨跌节奏提前排好，别等到旺季才开始想涨价
马上做：把未来 12 个月分成四档，写出每档的目标倍数与启用日期。
跟着做：为下一个旺季排一张分批上调时间表（每 15–20 天一档）。
不要做：旺季临时一次性跳涨　/　淡季等到空房才促销　/　价格日历排完全年不看
算法：档位倍数 = 该档目标房价 ÷ 平季基准房价（常见：旺季 1.2–1.4，淡季 0.85–0.95）　→　详见口袋书 No.25

演唱会那天卖爆了，第二天收到一堆差评

结论：演唱会、考试、展会这类日子，怎么提前锁定收益而不惹差评
马上做：建立一张本地事件日历：演出、赛事、考试、展会，提前录入未来 12 个月。
跟着做：给事件日设定涨幅上限（建议不超过平日的 1.8 倍）并写进规则。
不要做：无上限暴涨招致差评　/　只经营当天忽略溢出日　/　等活动全网扩散才开始动作
算法：事件日目标价 = 平季基准 × 事件倍数（建议 1.4–1.8，极端 2.0）　→　详见口袋书 No.26

餐厅天天排队，月底却没赚到钱

结论：把客房那套思路搬到餐厅：翻台、时段、人均三件事
马上做：算出本餐厅昨天晚餐时段的三个数：RevPASH、翻台率、人均消费。
跟着做：挑一个空闲时段设计错峰优惠，测算它的边际贡献是否为正。
不要做：只看营收不看翻台与人均　/　为提高翻台牺牲体验　/　用低价引流却不核算客群质量
算法：RevPASH = 时段总收入 ÷ (座位数 × 营业小时)　→　详见口袋书 No.27

客房满房的那天，宴会厅空了一整天

结论：别把宴会厅当赠品——它有时比客房更赚钱
马上做：给多功能厅定一份分时段价目表：上午、下午、晚间、全天。
跟着做：把宴会销售的话术改成“场租 + 餐饮 + 客房”三件套报价。
不要做：为争取餐饮而免收场租　/　只按场租判断接不接　/　忽略会议带来的连带客房
算法：综合贡献 = 场租 + 餐饮边际贡献 + 连带客房边际贡献　→　详见口袋书 No.28

民宿老板说：我们这行不讲究这个

结论：同一套逻辑，换三个参数就能用在别的业态上
马上做：先确认自己的库存单位是什么（间夜 / 套夜 / 月），再套用等效指标。
跟着做：找出一年里决定收益的那几十天，单独建一张日历。
不要做：认为房量少就用不上收益管理　/　照搬酒店的全部工具　/　忽略政策与平台规则风险
算法：收益 = 售出单位 × 单位价格　→　详见口袋书 No.29

花几十万上了系统，结果算出来的建议没人敢用

结论：什么时候该上系统，以及上系统前必须先准备好的四张表
马上做：先自查四张表：竞争群、历史数据、房型价格、细分渠道，缺哪张补哪张。
跟着做：用手工流程跑三个月并留记录，把规则写下来。
不要做：基础数据没准备好就采购系统　/　用演示效果做采购决策　/　上了系统就完全放弃人工判断
算法：年化收益 ≈ 年房晚收入 × RevPAR 提升幅度（通常 3%–7%）　→　详见口袋书 No.30

航空的收益管理，和酒店真的一样吗

结论：六个行业一张对照表，看懂内核不变、参数在变
马上做：挑一个你熟悉的行业，写出它的三个问题的答案。
跟着做：把这张对照表抄进你的笔记，遇到新业态时先套用。
不要做：被不同术语吓住　/　照搬工具却不换参数　/　认为跨行业必须从头学
算法：等效单位收益 = 期间收入 ÷ (可出租单位 × 期间)　→　详见口袋书 No.31

做了三年收益，还是会犯的低级错误

结论：把最容易犯的错一次列全，当作你案头的最后一本
马上做：把三十条打印出来，每季度核一次，标出本店当前命中哪几条。
跟着做：从命中的条目里只挑三条作为下一季度的整改项，不要一次改十条。
不要做：一次整改十条以上　/　把清单贴出来却从不核对　/　认为老手就不会犯基础错误
算法：决策质量 = 指标选对 × 顺序正确 × 前提成立 × 执行到位　→　详见口袋书 No.32

每周每月：收益会议怎么开

周期固定动作产出
每日看五个数 → 判断 → 一次动作调价记录一行
每周复盘上周七天数据 + 更新未来 30 天预测 + 与前厅、销售通气周报 + 下周策略
每月对比竞争三件套、检查渠道净值、调整竞争群名单月报 + 下月主策略
每季重画典型月预订曲线、校准 No-show 率、重设房型价差参数更新表
收益会议固定议程（建议 45 分钟）
1. 上周结果通报（5 分钟）：RevPAR / MPI / ARI / RGI 2. 本周预测与缺口（10 分钟）：哪些日子落后 3. 竞争情报（10 分钟）：谁动了价、动了什么房型 4. 本周动作清单（15 分钟）：≤3 条，明确负责人 5. 追踪上次会议的动作（5 分钟）
第四部分

自查清单与常见错误

二十问自查（每季度做一次）

  • 本店的指标口径是否已写下来并全店统一？
  • 竞争群名单是否还是那 3–5 家，有无过期？
  • 每天是否记录了竞争群的挂牌价？
  • 相邻房型的价差是否都在 8% 以上？
  • 高价房型是不是总被过早打开？
  • 所有渠道的净值是否算过并按净值排序？
  • 是否只用价格判断，从不看 pickup？
  • 提价是否 ≥12% 的跨度？
  • 是否只在预计满房的日子超售？
  • No-show 率是否每半年重算一次？
  • walk 预案是否写在纸上、人人都知道？
  • MinLOS/CTA 是否有明确的解除条件？
  • 官网与 OTA 的限制条件是否一致？
  • 团队报价是否都做过置换测算？
  • 是否有“本月可动用”的加值武器清单？
  • 每次调价是否留下了记录与结果？
  • 是否用不同星期属性的日子做过同比？
  • 发现落后时，是否先诊断了原因，而不是立刻降价？
  • 全年是否存在“为保证满房一路降价”的日子？
  • 过去 90 天，有没有一次完整的复盘文档？
用法：把这份清单打印出来，每个季度核一次；答不上来的那几条，就是下一季度的整改项。
