这一步具体怎么做

预测不是算命，是在你动手调价、锁房之前，先把「未来会来多少客人、以什么价格、从什么渠道来」看清。看清了，后面的决策才有锚；看清错了，后面全错。这一步占整个闭环价值的近一半。

操作步骤 · 3 个

一个动作一张牌

每个动作沿用同一套结构：先讲你会踩的坑，再讲怎么做、给公式、给今天就能做的动作、给工具。

动作 1
取历史数据　去年同周曲线做基准
⚠ 别踩这个坑：直接拿「上个月」当基准——但上个月可能有展会、疫情、装修，根本不是常态。

怎么做

拉过去 12-24 个月、同周期（同星期几、同节假日、同事件）的 OCC / ADR / RevPAR；按星期、按事件分层；把异常周（装修、疫情、大型会议）标注并剔除，得到一条干净的「常态基线」。

基线 = 过去 N 个同周期实际值的移动平均（建议 N≥12）

今天就能做的动作

①导出历史 ②按星期分层 ③标异常 ④算基线 ⑤存为「历史基线表」

🛠 工具：rm-engine 决策引擎 / 历史基线表模板　·　📄 在线预览　·　⬇ 下载Excel
动作 2
看在手预订　已订 + 渠道在途
⚠ 别踩这个坑：把「询价」当「已订」，以为房量还多，结果到期全没了。

怎么做

区分「确定性预订」（已担保/预付）与「询价/候补」；读当前在手房量 = 总房量 - 已订 - 锁房；看渠道在途（OTA 未确认、团队待签）。

在手可售 = 总房量 - 已确定性预订 - 已锁房

今天就能做的动作

每日开盘看在手可售；区分确定/询价；记录渠道在途

🛠 工具：PMS 房量视图 / 渠道在途表　·　📄 在线预览　·　⬇ 下载Excel
动作 3
算 Pace 进度　pickup ÷ 剩余天
⚠ 别踩这个坑：只看「今天订了多少」，不看「比去年今天快还是慢」。

怎么做

Pace = 今年至今累积预订量 ÷ 去年同期同口径累积量。Pace>1 表示需求强于去年（可提价）；<1 表示弱（保守/促销）。结合剩余天数判断追赶空间。

Pace = 本期至今预订量 ÷ 去年同期同口径预订量

今天就能做的动作

每周算一次 Pace；>1.1 标记提价窗口；<0.9 标记促销窗口

🛠 工具：预订进度表 / pickup 曲线　·　📄 在线预览　·　⬇ 下载Excel
这一步的节奏（每天 / 每周 / 每月 / 每年）
  • 每天　开盘看在手可售 + Pace，5 分钟。
  • 每周　周一做未来 7-14 天预测，更新基线。
  • 每月　滚动未来 90 天预测，校准季节系数。
  • 每年　用全年实际修正历史基线权重。

本页行动清单
  1. 拉 12+ 个月同周期历史，剔除异常周
  2. 建「历史基线表」并存档
  3. 每日区分确定预订与询价，看在手可售
