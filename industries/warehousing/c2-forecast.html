需求预测

仓储的需求不是「有多少货要存」，而是两件必须分开预测的事：未来每个时点会有多少库位天被占用（决定仓位能不能卖出去、卖多少钱），以及会有多少订单行与出库件数需要履约（决定要配多少人、多少叉车、多少月台）。两者的驱动因素完全不同——仓位需求跟着客户的生产与备货节奏走，履约需求跟着促销与流量走。

核心要点

四条要记住的

  1. 四个提前期，各管一件事。年度与季度（提前 3–12 个月）用于仓库租约谈判、扩容与自动化设备投资；月度（提前 4–8 周）用于仓位预留、长短期合约配比与人力编制；周与日（提前 1–2 周）用于排班、月台预约与外仓预案；小时级用于大促期间的波次排产与临时工调度。
  2. 数据来源必须跨出仓库。仓内数据（历史入库 / 出库 / 在库结构与账龄、SKU 件型与 ABC 分类、月台与叉车稼动率）只是一半，另一半在客户那里：客户销售计划与促销日历、生产排产、船期与到港预报、平台大促报名量、预售定金数据。拿不到客户侧数据，预测只能做到月度精度。
  3. 事件驱动是主要误差源。电商节（618 预热、双11 预售与两波爆发、双12、年货节）、开学季与换季上新、春节前工厂停工与节后集中到货、直播带货的单日爆量、海关通关节奏变化、周边竞品仓降价引发的转仓。
  4. 误差代价不对称，必须输出区间并绑定预案。低估入库量 → 爆仓、拒收或临时租外仓（成本可达常态 2–3 倍且触发履约超时违约）；低估出库量 → 人力不足、发货超时、客户店铺评分下降；高估 → 空置与人力的双重浪费。因此预测要给出上限 / 基准 / 下限三档，并对应绑定外仓额度与临时工预案。

常见错误

这个行业容易踩的坑

  • 只按历史均值外推——忽略客户促销日历与平台大促节奏，双11 前两周必然爆仓。
  • 只信客户的口头承诺量——客户报的量普遍虚高（怕拿不到仓位）或虚低（怕被涨价），必须与其历史实际到货 / 出货比对后打折使用。
  • 只预测总量不预测结构——出库件数对了但订单碎片度翻倍，分拣人力直接崩掉。
  • 把大促峰值当成常态去扩容——按峰值配的仓与人，在剩下的十一个月里全是固定成本。
自测

两道题

第 1 题　为什么仓储需求预测必须把「入库量」和「出库量」分成两条线分别预测？
解析 · 入库量跟的是客户的生产与备货节奏（决定库位天被占用多少、还能不能接新客户），出库量跟的是促销与流量（决定要多少人、多少月台、能不能按时发货）。大促期间两者还不同步——入库峰值通常提前 7–15 天到达，出库峰值在爆发当天，混成一条线预测必然在其中一个环节失控。
第 2 题　某客户为双11 报的备货量比其历史同期实际到货高出 60%。预测环节的正确做法是？
解析 · 客户的报量是谈判数字而不是预测值，必须与其历史实际履约数据比对后修正。正确做法有三层：以历史实际为基准给出上限 / 基准 / 下限三档、按上限预置外仓与临时工等弹性资源（弹性成本远低于爆仓成本）、用超量附加费条款让客户在报量时说实话。直接按报量预留会把旺季仓位锁死，简单打折则没有任何兜底。
