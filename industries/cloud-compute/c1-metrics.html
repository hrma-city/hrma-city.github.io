云算力专业课 · C1

指标体系

云算力的产能单位是「GPU卡·时」，与酒店房晚最大的差别是——它可切分、可抢占、可跨机拼装，但几乎不可储存：今天空闲的卡时不会在明天变成两倍的卡时，空转一小时的损失永远找不回来。同时同一张卡可以按整机、按单卡、按 vGPU 切片出售，口径不同，「利用率」三个字的含义完全不同。

核心要点

四条要记住的

  1. 单卡时收入 RevPAGH = 算力收入 ÷ 可用 GPU 卡·时。云算力版 RevPAR，把「卖了多少」和「卖多贵」压成一个数，是衡量集群真实产出的核心指标；分子只计算力服务收入，不含存储与网络溢价，分母是物理可用卡时而非已售出卡时。
  2. GPU 利用率 = 有效占用卡时 ÷ 可用卡时。必须用 SM 利用率或算力吞吐做校核：分配出去 100% 但 SM 利用率只有 40%，是典型的「分而不算」，会把闲置伪装成满载。
  3. 实现单价 = 算力收入 ÷ 计费卡时。云算力版 ADR，必须按按需／抢占／预留三类业务分别拆解，一个混合均价会掩盖抢占占比上升导致的价格稀释。
  4. 闲置率 = （可用卡时 − 计费卡时）÷ 可用卡时。闲置不是零成本，折旧、电力、机房与运维照常发生；同时要单独看碎片率——因拓扑或显存不匹配而分配不出去的卡时，是「看得见却卖不掉」的闲置。

常见错误

这个行业容易踩的坑

  • 只看分配率不看 SM 利用率——卡分配出去了但作业在等数据、等参数或单卡 batch 太小，报表满载实际空转。
  • 只看利用率不看单位收益——用三年长租五折把集群填满，利用率 95% 而 RevPAGH 只有同行一半。
  • 把长租承诺收入一次性计入当期——应按卡时履约进度摊销，否则当期收入与产能消耗不匹配。
  • 把闲置当成零成本——折旧、电力、机房与带宽是刚性支出，闲置卡时的真实损失是「单卡时毛利 × 闲置卡时」。
自测

两道题

第 1 题　云算力业态里，对应酒店 RevPAR 的等价核心指标是哪一个？
解析 · RevPAR 的本质是「单位可售产能创造的平均收入」，酒店的可售产能是可售房晚，云算力的可售产能是可用 GPU 卡·时，所以等价指标是算力收入 ÷ 可用卡·时。实现单价只是价格维度（相当于 ADR），利用率只是数量维度（相当于 OCC），只有单卡时收入把两个杠杆压成一个数；排队时长是服务指标，不直接反映产出。
第 2 题　某集群报表显示 GPU 分配率 98%，但 SM 利用率长期只有 35%。以下判断最合理的是？
解析 · 分配率衡量的是「卡有没有被占住」，SM 利用率衡量的是「卡有没有在算」。两者背离 60 个百分点，典型原因是作业在等数据加载、等参数同步、单卡 batch 过小、或分配后迟迟未启动。此时涨价只会把客户推向竞品，正确动作是先做空转治理（数据预取、检查点优化、超时回收），把有效算力释放出来，再看是否真有产能缺口。
