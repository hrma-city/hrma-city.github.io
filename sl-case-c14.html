林岚做的第一件事：查竞争价格这个输入。

RMS 抓的竞争价格是从三个 OTA 爬取的"最低可售价"。她把五家竞品 11/22 的价格逐个打开看：

"五个竞品里，三个抓错了。"林岚说，"RMS 抓的是公开渠道的'最低挂牌价'，但那不是 BAR——是各家带栅栏的促销价。"

她重算竞争组合均价：

"RMS 认为对手均价 607，实际是 672。"

决策点 · 您会怎么选

决策点一：系统和人冲突，听谁的？

  • 都不盲从。先查输入
  • 判据：输入对了听系统，输入错了听人。

决策点二：系统在哪些事上比人强？

  • 算得快、不情绪化、能同时处理几百个日期和竞品数据
  • 判据：批量、重复、需要算术的事，交给系统。

决策点三：人在哪些事上比系统强？

  • 知道系统不知道的信息（待确认订单、未录入的事件）、判断数据质量、为结果负责
  • 判据：信息不对称和数据清洗，交给人。

决策点四：怎么让系统越来越准？

  • 覆写时记录原因、定期清洗输入、追踪准确度
  • 判据：把"覆写"当成对系统的训练，不是对抗。

输入常见错误人工核查方法

规矩内容

一句话记住

信输入，不信结论。

系统算得快、不情绪化，但它不知道您手上那笔还没确认的团单，也分不清对手的促销价和 BAR——

而这五分钟的核对，就是收益经理最值钱的地方。

附录 A · 名词解释（35 条）

① OCC 出租率＝ 已售房晚 ÷ **可售房晚**。 分母是"能卖的房"，不是"有的房"——维修、自用、业主预留、免费房都不算可售。本店基线 68%。 → 见 案例 01、案例 02
② ADR 平均房价＝ 客房收入 ÷ **已售房晚**。 注意分母和 OCC 不同（OCC 用可售，ADR 用已售）——这是全行业最容易记混的地方。本店基线 620 元。 → 见 案例 01
③ RevPAR 每间可售房收入＝ 客房收入 ÷ 可售房晚 ＝ OCC × ADR。 **它是收入指标，不是利润指标**：只看客房收入，不看成本、不看渠道佣金、不看餐饮联动。 → 见 案例 01（它的陷阱）、案例 04
④ 可售房晚＝ 总房晚 − 维修 − 自用 − 业主预留 − 免费房。 本店 300 间房，常态可售约 291 间（含维修与预留）。**口径错一个字，后面查表得出的动作全错。** → 见 案例 02
⑤ 预订进度 Pickup：某个目标日期的**在手间夜在一段时间内的新增量**。 在手是存量，Pickup 是增速。**展会这类临期爆发的需求，看在手会误判，看 Pickup 斜率才准。** → 见 案例 05
⑥ BAR 最佳可用房价：公开渠道上所有人都能看到、随时可订的基准价。 **它是全年的锚**：动一次，明年的协议谈判、会员预期、OTA 比价全都跟着变。 → 见 案例 06、案例 09
⑦ 价格栅栏 Rate Fence：拿到低价必须满足的条件。四道闸： 提前预订 / 不可改退 / 限定渠道 / 限定房型或限量。 **栅栏的本质不是限制，是筛选**——让愿意付高价的人找不到低价。 → 见 案例 06、案例 10
⑧ 置换分析：接一单团队，要算"这单的贡献"减去"被它挤掉的那部分的贡献"。 **看的不是"这单赚不赚"，是"比不接多赚多少"。**净收益 > 0 才接。 → 见 案例 07、案例 12
⑨ 保护位 Protection Level：给高价客源保留的房量，低价档不能动。 ＝ 预测高价需求 × 安全系数（1.0–1.15）。**先算留多少，剩下的才是能便宜卖的量。** → 见 案例 07
⑩ 低价可售上限＝ 可售房晚 − 保护位。 超过这个上限放低价，就是在挤掉本可高价售出的房。**本例上限 91 间，团队要 120 间 → 只接 80。** → 见 案例 07
⑪ 最短住期 MLOS：要求最少住几晚。旺季用来挡掉只住一晚的客人， 让 2 晚以上的高价客住得进来。展会周常设 MLOS 2。 → 见 案例 05
⑫ ARI 平均房价指数＝ 本店 ADR ÷ 竞争组合 ADR。 衡量"卖得贵不贵"。**本店合理区间 1.02–1.10**（位置溢价）。超出才考虑跟价。 → 见 案例 09
⑬ MPI 市场渗透指数＝ 本店 OCC ÷ 竞争组合 OCC。 衡量"抢到的份额够不够"。合理区间 0.95–1.05。 → 见 案例 09
⑭ RGI 收入产生指数＝ 本店 RevPAR ÷ 竞争组合 RevPAR ＝ MPI × ARI。 **最终指标**：份额和价格都赢，RGI 才高；只赢一个不算赢。 → 见 案例 09
⑮ NRevPAR 净 RevPAR＝ (客房收入 − 渠道成本) ÷ 可售房晚。 扣掉 OTA 佣金之后的真实收入层。**OTA 占比一涨，RevPAR 和 NRevPAR 就会分家。** → 见 案例 04、案例 08
⑯ GOPPAR 每间可售房毛利＝ 部门毛利 ÷ 可售房晚。 **经营层指标，比 RevPAR 更接近真相。**RevPAR 涨、GOPPAR 跌＝用利润换出租率。 → 见 案例 01、案例 04
⑰ 量差价差归因：把 RevPAR 的变动拆成"多卖了多少"和"卖贵了多少"。 量差＝ΔOCC × 去年 ADR；价差＝ΔADR × 今年 OCC。**涨在量上说明靠多卖，涨在价上说明靠卖贵。** → 见 案例 04
⑱ 渠道净价＝ 挂牌价 − 佣金/返点/积分成本。 **排序渠道不是看谁挂牌价高，是看净价 + 联动消费 − 变动成本之后的贡献。** 本店：上门 613 / 官网会员 601 / 协议 580 / 团队 520 / OTA 基础 521 / OTA 曝光计划 460。 → 见 案例 08
⑲ 增量率＝ (渠道带来的间夜 − 关掉后其他渠道补回的间夜) ÷ 该渠道间夜。 **衡量这个渠道到底在带新客，还是在吃自己的客源。**本店 OTA 增量率 80% → 值得保留基础投放。 → 见 案例 08
⑳ 超售：在满房基础上多卖，用来对冲 No-show。 **必须按三步法**（算 No-show 率 → 乘保守系数 → 准备兜底酒店），不能拍脑袋。 → 见 案例 13
㉑ No-show：订了没来、也没取消。 **各渠道差别极大**：OTA 现付 12%、协议 5%、OTA 预付 2%、团队 1%。 超售量必须按"当天客源结构"加权算，不能用一个历史平均值。 → 见 案例 13
㉒ 季节性指数＝ 某月三年平均 RevPAR ÷ 全年平均 RevPAR。 拆年度预算到月的第一步。**指数 >1.1 的月份增长空间小，<0.9 的月份（若今年做砸了）修复空间大。** → 见 案例 11
㉓ 三场景预算：保守 / 基准 / 乐观三套目标，每套对应一套动作包。 **预算不是预测**：预测每周滚动、用来定价格；预算一年一次、用来管成本与考核。 → 见 案例 11
㉔ 变动成本：多卖一间房新增的成本（洗涤、易耗、能耗）。 **本店约 95 元/间夜。**固定成本（房租、人工、折旧）不随间夜变化—— 所以"空着也是空着，多卖一间至少赚 300"这句话，错在忽略了它挤掉的是本可卖 600 的房。 → 见 案例 01
㉕ 尾房价：夜审前最后几小时的低价，**仅 walk-in 与 OTA 尾单，官网不挂**。 本店规则：21:00 后启动，480 元（高于变动成本且有贡献，且不会变成明天的挂牌价）。 → 见 案例 03
㉖ 人均贡献＝ (房费 + 餐饮 + 会场 − 所有成本) ÷ 人数。 会议单的快速分级指标：**>600 为 A 级（主动出击），250–400 为 C 级（只在淡季接），<250 不接。** → 见 案例 12
㉗ RMS 收益管理系统：算最优价、处理几百个日期、抓竞品价格的引擎。 **它强在批量与算术，弱在不知道您手上那笔还没确认的团单。** → 见 案例 14
㉘ 覆写：不执行系统的建议。三条规矩： **必记原因、限幅 ±10%、月度复盘成功率。**覆写是对系统的训练，不是对抗。 → 见 案例 14
㉙ 竞争组合 Compset：与本店抢同一批客人的那几家。 本店五家：A 880（高端商务）/ B 680（最直接对手）/ C 560（抢会议团队）/ D 720（精品）/ E 520（新店低价）。 → 见 案例 09
㉚ 房型价差：相邻房型的价格差。本店：高级 640 / 豪华 780 / 行政 1,080 / 套房 1,880。 **差价越大的房型越要保护**——团队单优先砍高价房型的份额。 → 见 案例 07
㉛ 会员专享价：需登录才能看到的低价层。本店 499（提前 7 天 + 不可退）。 **它是最常用的栅栏**：能降价，但不进入公开锚点。 → 见 案例 06、案例 10
㉜ 价值包：不降 BAR 而送等值服务（双早/积分/延迟退房/停车）。 **成本 15–40 元，感知价值 40–120 元，且不伤 BAR。**能用价值包解决的，不要用降价解决。 → 见 案例 06、案例 09
㉝ 每日取数清单：字段 / 来源 / 口径 / 截止时间写死的取数表。 本店五项：可售房晚（PMS 08:30）、已售房晚（账务反推 09:00）、在手（CRS）、Pickup（CRS）、竞品价（10:00）。 **流程的价值在于把"查"变成例外处理，而不是日常动作。** → 见 案例 02
㉞ 调价台账：每一次价格动作的登记（日期/动作/依据/待观察结果）。 **没有台账就没有复盘**——下个月没法回答"上次这么做对不对"。 → 见 案例 03、案例 04
㉟ 机会成本：占用某资源而放弃的其他收益。 **宴会厅的机会成本＝被推掉的那场会**——这是置换分析里最容易漏掉的一项。 → 见 案例 12

附录 C · 流程 SOP（12 条）

S1 每日三步：看数（8:30，盯未来哪天要出事）→ 查表（先表 B 库存、后表 A 价格）→ 执行（团队/竞品/尾房）→ 17:30 记台账。 → 案例 03
S2 判定表调用顺序：**表 B（库存限制）→ 表 A（价格）→ 表 L（应急）**。 顺序不能反：门还开着就降价，等于给本来能高价卖的房打折。 → 案例 03
S3 每日取数：固定五项，固定来源，固定口径，固定截止时间。两个系统对不上时，先查四类脏数据（时差/No-show/团队/重复），不是选一个信。 → 案例 02
S4 团队询价处理：问清日期/房型/餐饮会议 → 置换分析 → **按天拆开算**（不同日期结论可能相反）→ 净收益为正的天数才接，其余帮客户协调周边。 → 案例 05 案例 07
S5 竞争响应三步：① 算 ARI 是否在合理区间 → ② 查历史同情境跟价的结果 → ③ 判客群是否重叠。三条都指向"跟"才跟。 → 案例 09
S6 库存分配五步：预测高价需求（按房型）→ 设保护位 → 算低价上限 → 按房型分配（高价房型优先保护）→ 随 Pickup 滚动调整。 → 案例 07
S7 超售三步：按渠道算 No-show 率 → 乘保守系数 → 锁定 2 家周边酒店 + 明确补偿标准。 → 案例 13
S8 置换分析六项：房费 + 宴会餐饮收入 − 变动成本 − 餐饮成本 − 被挤散客贡献 − **被推掉的宴会机会成本**。 → 案例 12
S9 降价决策：算打平涨幅（F5）→ 判断可行性（<15% 直接做，15–30% 必须配栅栏且限量，>30% 改做价值包）→ 设置四道栅栏 → 限量 → 记账。 → 案例 06
S10 年度预算：算季节性指数 → 按可实现性加权拆月（把增长压在今年做砸的月份）→ 三场景 → 每套配动作包 → 对外报基准、对内按保守做成本。 → 案例 11
S11 前台授权：**不创造价格、不口头承诺、不越权放房**。满房后只推荐周边，不放房；尾房价须 21:00 后按系统价。 → 案例 13
S12 RMS 复核：每次看建议先核三个输入（竞品价是不是 BAR / 历史参照日有没有事件 / 在手含不含待确认单）→ 输入对就听系统，输入错就覆写 → 覆写记原因、限幅 ±10%、月度复盘。 → 案例 14

附录 A · 名词解释（35 条）

① OCC 出租率＝ 已售房晚 ÷ **可售房晚**。 分母是"能卖的房"，不是"有的房"——维修、自用、业主预留、免费房都不算可售。本店基线 68%。 → 见 案例 01、案例 02
② ADR 平均房价＝ 客房收入 ÷ **已售房晚**。 注意分母和 OCC 不同（OCC 用可售，ADR 用已售）——这是全行业最容易记混的地方。本店基线 620 元。 → 见 案例 01
③ RevPAR 每间可售房收入＝ 客房收入 ÷ 可售房晚 ＝ OCC × ADR。 **它是收入指标，不是利润指标**：只看客房收入，不看成本、不看渠道佣金、不看餐饮联动。 → 见 案例 01（它的陷阱）、案例 04
④ 可售房晚＝ 总房晚 − 维修 − 自用 − 业主预留 − 免费房。 本店 300 间房，常态可售约 291 间（含维修与预留）。**口径错一个字，后面查表得出的动作全错。** → 见 案例 02
⑤ 预订进度 Pickup：某个目标日期的**在手间夜在一段时间内的新增量**。 在手是存量，Pickup 是增速。**展会这类临期爆发的需求，看在手会误判，看 Pickup 斜率才准。** → 见 案例 05
⑥ BAR 最佳可用房价：公开渠道上所有人都能看到、随时可订的基准价。 **它是全年的锚**：动一次，明年的协议谈判、会员预期、OTA 比价全都跟着变。 → 见 案例 06、案例 09
⑦ 价格栅栏 Rate Fence：拿到低价必须满足的条件。四道闸： 提前预订 / 不可改退 / 限定渠道 / 限定房型或限量。 **栅栏的本质不是限制，是筛选**——让愿意付高价的人找不到低价。 → 见 案例 06、案例 10
⑧ 置换分析：接一单团队，要算"这单的贡献"减去"被它挤掉的那部分的贡献"。 **看的不是"这单赚不赚"，是"比不接多赚多少"。**净收益 > 0 才接。 → 见 案例 07、案例 12
⑨ 保护位 Protection Level：给高价客源保留的房量，低价档不能动。 ＝ 预测高价需求 × 安全系数（1.0–1.15）。**先算留多少，剩下的才是能便宜卖的量。** → 见 案例 07
⑩ 低价可售上限＝ 可售房晚 − 保护位。 超过这个上限放低价，就是在挤掉本可高价售出的房。**本例上限 91 间，团队要 120 间 → 只接 80。** → 见 案例 07
⑪ 最短住期 MLOS：要求最少住几晚。旺季用来挡掉只住一晚的客人， 让 2 晚以上的高价客住得进来。展会周常设 MLOS 2。 → 见 案例 05
⑫ ARI 平均房价指数＝ 本店 ADR ÷ 竞争组合 ADR。 衡量"卖得贵不贵"。**本店合理区间 1.02–1.10**（位置溢价）。超出才考虑跟价。 → 见 案例 09
⑬ MPI 市场渗透指数＝ 本店 OCC ÷ 竞争组合 OCC。 衡量"抢到的份额够不够"。合理区间 0.95–1.05。 → 见 案例 09
⑭ RGI 收入产生指数＝ 本店 RevPAR ÷ 竞争组合 RevPAR ＝ MPI × ARI。 **最终指标**：份额和价格都赢，RGI 才高；只赢一个不算赢。 → 见 案例 09

㉓ 三场景预算：保守 / 基准 / 乐观三套目标，每套对应一套动作包。 **预算不是预测**：预测每周滚动、用来定价格；预算一年一次、用来管成本与考核。 → 见 案例 11
㉔ 变动成本：多卖一间房新增的成本（洗涤、易耗、能耗）。 **本店约 95 元/间夜。**固定成本（房租、人工、折旧）不随间夜变化—— 所以"空着也是空着，多卖一间至少赚 300"这句话，错在忽略了它挤掉的是本可卖 600 的房。 → 见 案例 01
㉕ 尾房价：夜审前最后几小时的低价，**仅 walk-in 与 OTA 尾单，官网不挂**。 本店规则：21:00 后启动，480 元（高于变动成本且有贡献，且不会变成明天的挂牌价）。 → 见 案例 03
㉖ 人均贡献＝ (房费 + 餐饮 + 会场 − 所有成本) ÷ 人数。 会议单的快速分级指标：**>600 为 A 级（主动出击），250–400 为 C 级（只在淡季接），<250 不接。** → 见 案例 12
㉗ RMS 收益管理系统：算最优价、处理几百个日期、抓竞品价格的引擎。 **它强在批量与算术，弱在不知道您手上那笔还没确认的团单。** → 见 案例 14
㉘ 覆写：不执行系统的建议。三条规矩： **必记原因、限幅 ±10%、月度复盘成功率。**覆写是对系统的训练，不是对抗。 → 见 案例 14
㉙ 竞争组合 Compset：与本店抢同一批客人的那几家。 本店五家：A 880（高端商务）/ B 680（最直接对手）/ C 560（抢会议团队）/ D 720（精品）/ E 520（新店低价）。 → 见 案例 09
㉚ 房型价差：相邻房型的价格差。本店：高级 640 / 豪华 780 / 行政 1,080 / 套房 1,880。 **差价越大的房型越要保护**——团队单优先砍高价房型的份额。 → 见 案例 07
㉛ 会员专享价：需登录才能看到的低价层。本店 499（提前 7 天 + 不可退）。 **它是最常用的栅栏**：能降价，但不进入公开锚点。 → 见 案例 06、案例 10
㉜ 价值包：不降 BAR 而送等值服务（双早/积分/延迟退房/停车）。 **成本 15–40 元，感知价值 40–120 元，且不伤 BAR。**能用价值包解决的，不要用降价解决。 → 见 案例 06、案例 09
㉝ 每日取数清单：字段 / 来源 / 口径 / 截止时间写死的取数表。 本店五项：可售房晚（PMS 08:30）、已售房晚（账务反推 09:00）、在手（CRS）、Pickup（CRS）、竞品价（10:00）。 **流程的价值在于把"查"变成例外处理，而不是日常动作。** → 见 案例 02
㉞ 调价台账：每一次价格动作的登记（日期/动作/依据/待观察结果）。 **没有台账就没有复盘**——下个月没法回答"上次这么做对不对"。 → 见 案例 03、案例 04
㉟ 机会成本：占用某资源而放弃的其他收益。 **宴会厅的机会成本＝被推掉的那场会**——这是置换分析里最容易漏掉的一项。 → 见 案例 12

附录 C · 流程 SOP（12 条）

S1 每日三步：看数（8:30，盯未来哪天要出事）→ 查表（先表 B 库存、后表 A 价格）→ 执行（团队/竞品/尾房）→ 17:30 记台账。 → 案例 03
S2 判定表调用顺序：**表 B（库存限制）→ 表 A（价格）→ 表 L（应急）**。 顺序不能反：门还开着就降价，等于给本来能高价卖的房打折。 → 案例 03
S3 每日取数：固定五项，固定来源，固定口径，固定截止时间。两个系统对不上时，先查四类脏数据（时差/No-show/团队/重复），不是选一个信。 → 案例 02
S4 团队询价处理：问清日期/房型/餐饮会议 → 置换分析 → **按天拆开算**（不同日期结论可能相反）→ 净收益为正的天数才接，其余帮客户协调周边。 → 案例 05 案例 07
S5 竞争响应三步：① 算 ARI 是否在合理区间 → ② 查历史同情境跟价的结果 → ③ 判客群是否重叠。三条都指向"跟"才跟。 → 案例 09
S6 库存分配五步：预测高价需求（按房型）→ 设保护位 → 算低价上限 → 按房型分配（高价房型优先保护）→ 随 Pickup 滚动调整。 → 案例 07
S7 超售三步：按渠道算 No-show 率 → 乘保守系数 → 锁定 2 家周边酒店 + 明确补偿标准。 → 案例 13
S8 置换分析六项：房费 + 宴会餐饮收入 − 变动成本 − 餐饮成本 − 被挤散客贡献 − **被推掉的宴会机会成本**。 → 案例 12
S9 降价决策：算打平涨幅（F5）→ 判断可行性（<15% 直接做，15–30% 必须配栅栏且限量，>30% 改做价值包）→ 设置四道栅栏 → 限量 → 记账。 → 案例 06
S10 年度预算：算季节性指数 → 按可实现性加权拆月（把增长压在今年做砸的月份）→ 三场景 → 每套配动作包 → 对外报基准、对内按保守做成本。 → 案例 11
S11 前台授权：**不创造价格、不口头承诺、不越权放房**。满房后只推荐周边，不放房；尾房价须 21:00 后按系统价。 → 案例 13
S12 RMS 复核：每次看建议先核三个输入（竞品价是不是 BAR / 历史参照日有没有事件 / 在手含不含待确认单）→ 输入对就听系统，输入错就覆写 → 覆写记原因、限幅 ±10%、月度复盘。 → 案例 14
