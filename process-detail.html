环节 1　确定竞组与市场定位

1.1

竞组筛选：选谁进竞组

触发条件

新店筹备期、每年一次、或市场结构发生明显变化时启动。

涉及表

表 C · 表 D

判定规则

「三同」标准：同档次（ADR 差距 ±20% 以内）、同商圈（3 公里内或共享同一客源）、同客群（商旅/度假/会议）。数量控制在 3–5 家：少于 3 家受单店促销扰动大，多于 5 家易混入不同档次。

执行动作

① 列 10–15 家备选；② 按三同标准打分筛选；③ 定 3–5 家并写下选择理由；④ 报业主/管理层备案，避免事后争议。

案例

某店把两家五星酒店纳入竞组，导致 ARI 常年 65，管理层误判「价格严重偏低」而连续提价，OCC 掉到 62%、RGI 反跌——真正抢客人的三家同档酒店（ADR ¥700 左右）根本不在名单里。（详见案例集 案例1）

自测题

一家 320 间中高端酒店（ADR ¥680）要选竞组，以下哪家最应该被选入？

  1. 3 公里内、ADR ¥1,050 的五星酒店
  2. 3 公里内、ADR ¥700 的同档次酒店
  3. 10 公里外、ADR ¥680 的同档次酒店
  4. 同城 ADR ¥300 的经济型酒店
答案：B　竞组要看「三同」：同档次、同商圈、同客群。五星（¥1,050）档次差太远会拉高竞组均价、让你的 ARI 虚低；10 公里外不同客源；经济型不在一个市场。只有 B 同时满足三同。
1.2

竞组复核：什么时候该换

触发条件

每季度固定复核一次；出现停业装修、换品牌、新店开业、档次变动时立即复核。

涉及表

表 C · 表 D

判定规则

复核四问：① 这家还在营业吗？② 档次变了吗？③ 价格带还接近吗？④ 它还在抢我的客人吗？任一项为否即移出或替换。特别注意停业装修期的酒店仍会挂牌低价，会污染竞组均价。

执行动作

① 每季度导出竞组挂牌价与状态；② 剔除停业/装修/换牌的；③ 补充新开业的同档酒店；④ 更新后重算近 90 天指数，观察跳变是否正常。

案例

竞组中一家酒店停业装修半年，但名单未更新，其低价挂牌持续拉低竞组均价。本店据此认为「价格已偏高」，错过旺季提价窗口，三个月 RevPAR 比可达水平低约 6%。（案例1）

自测题

竞组里的一家酒店停业装修，但它仍在 OTA 上低价挂牌。正确的做法是？

  1. 保留，反正数据还在
  2. 立即移出竞组，等其恢复正常营业且价格稳定后再评估是否纳入
  3. 保留但手动把它的价格调高
  4. 把整个竞组都换掉
答案：B　停业/装修期的酒店挂牌价不代表真实竞争，会污染竞组均价，让你的 ARI 虚高、从而不敢提价。应立即移出，恢复营业并价格稳定后再评估。
1.3

基准校准：统一指数口径

触发条件

确定竞组后、以及每次更换数据源（如换 RMS 或收益系统）时必须校准。

涉及表

表 C · 表 D

判定规则

统一三个口径：① 含税/不含税；② 含早/不含早；③ 纳入计算的房型范围。RGI = MPI × ARI，三者必须是同一口径、同一时间段、同一竞组。口径不一致时指数毫无意义。

执行动作

① 写死口径说明（含税、含早、房型范围）；② 每月核对竞组数据是否为同口径；③ 用 RGI = MPI × ARI 验算，偏差 >2% 说明口径有问题。

案例

某店本店数据含早、竞组数据不含早，导致 ARI 常年虚高 8–10 个点，管理层误以为价格已领先，实际落后市场。（口径校准要点）

自测题

本店 ADR 含双早 ¥680，竞组数据是不含早的 ¥620。直接相除得到 ARI = 110，这个结论可靠吗？

  1. 可靠，110 说明价格领先
  2. 不可靠，口径不一致（含早 vs 不含早），应先把早餐价值剥离再比
  3. 不可靠，应该改用 OCC 比较
  4. 可靠，但要把早餐成本加回去
答案：B　指数比较的前提是同口径。含早与不含早相差通常 ¥60–120/间，足以让 ARI 偏差 10 个点以上。必须先把早餐价值从本店 ADR 中剥离，或改用竞组的含早价。

环节 2　年度预算与目标分解

2.1

目标拆解：按日型与季节分，不平均分

触发条件

每年 10–11 月启动下一年度预算；季度滚动校准。

涉及表

表 A · 表 N

判定规则

年度目标 不能 ÷12。按「季节系数 × 日型系数」拆到月、周、日：旺季定高价高目标，淡季定保量目标。日型至少分 D1 峰值 / D2 高涨 / D3 平峰 / D4 低谷。

执行动作

① 先算去年各月收入占比作为季节系数基准；② 叠加已知的展会/节假日/事件；③ 把年度目标按月分配；④ 再按日型拆到周与日。

案例

某店把年度目标直接 ÷12。结果淡季团队为凑数低价甩卖，旺季早已卖满、无房可提价。全年总量勉强达标，但 GOPPAR 比按季节分解低约 4%。（案例2）

自测题

一家酒店 7–8 月暑期和 11 月展会月占全年收入 34%，1–2 月仅占 9%。年度预算应该怎么分？

  1. 年度目标 ÷12，每月一样
  2. 按季节系数与日型分解，旺季高目标、淡季保量目标
  3. 全部压到旺季
  4. 平均分配再每月微调
答案：B　÷12 会同时犯两个错：淡季为凑数低价甩卖（伤价），旺季早已卖满无房可提价（少赚）。必须按季节系数 × 日型分解。
2.2

指标设定：禁单指标考核

触发条件

制定年度目标与各部门 KPI 时确定。

涉及表

表 A · 表 N

判定规则

OCC 与 ADR 必须成对考核，或直接用 RevPAR / GOPPAR。单考核 OCC 会诱导前台低价甩卖；单考核 ADR 会导致高空置。想看渠道真实贡献用 NRevPAR，想看经营质量用 GOPPAR。

执行动作

① 前台与销售共用 RevPAR 或 GOPPAR 作为主指标；② OCC 与 ADR 作为辅助指标成对出现；③ 把 NRevPAR 与直销占比纳入渠道考核。

案例

某店只考核 OCC（85%），淡季前厅长期以 ¥380 抛售（BAR ¥680）。OCC 做到 86%，但 ADR 从 ¥620 掉到 ¥495，GOPPAR 因清洁布草成本上升而下降。（案例2）

自测题

只把 OCC 作为前台唯一考核指标，最可能发生什么？

  1. 房价和出租率同步上涨
  2. 前台为冲出租率低价抛售，ADR 下滑、GOPPAR 下降
  3. 没任何影响
  4. 员工更积极推销高价房
答案：B　单指标必然被博弈。考核 OCC，前台就会用价格换出租率；考核 ADR，前台就会惜售导致高空置。必须成对考核，或直接用 RevPAR / GOPPAR。
2.3

滚动校准：每月对比实际与预算

触发条件

每月初（通常 5 日前）完成上月复盘与未来 3 个月滚动预测。

涉及表

表 N

判定规则

滚动预测：实际（已发生）+ 最新预测（未来 3 个月）。偏差超过 ±5% 要写原因与纠偏动作；连续两个月偏差同向说明预算模型有问题，不是执行问题。

执行动作

① 每月 5 日前出上月实际 vs 预算；② 更新未来 3 个月预测；③ 偏差 >±5% 写原因与动作；④ 年度中若市场结构变化，正式修订预算。

案例

某店预算定完一年不校准，到 9 月才发现全年偏离 11%，已来不及调整。（滚动校准机制要点）

自测题

连续两个月实际收入都比预算低 8%，收益经理首先应该做什么？

  1. 要求销售加大折扣力度
  2. 先判断是预算模型问题还是执行问题，再决定纠偏动作
  3. 把年度目标调低
  4. 换掉收益经理
答案：B　连续同向偏差通常说明预算假设（季节系数、事件日历、客群结构）错了，属于模型问题；偶发偏差才是执行问题。先诊断再动手，否则会越纠越偏。

环节 3　价格体系与房型价差搭建

3.1

BAR 锚定：以最佳弹性房价为锚

触发条件

搭建价格体系时确定，每次大调价前复核。

涉及表

表 A · 表 F

判定规则

BAR = 当日散客公开渠道可售的最高弹性房价，不是虚高的门市价。所有折扣（协议、会员、早鸟、促销）都以 BAR 为基准展开。用门市价当 BAR，折扣体系必然层层叠叠、价格打架。

执行动作

① 统计近 90 天散客实际成交均价作为 BAR 基准；② 确认 BAR 低于或等于门市价；③ 所有渠道折扣以 BAR 为锚计算；④ 每月复核一次。

案例

某店把门市价 ¥1,280 当 BAR，实际成交均价只有 ¥620。以 ¥1,280 为锚打折，OTA 挂 5 折、协议 6 折、会员 7 折，同一房型不同渠道差价 ¥300+，引发大量投诉并流失。（案例3）

自测题

一家酒店门市价 ¥1,280，但近 90 天散客实际成交均价是 ¥620。BAR 应该定为多少？

  1. ¥1,280（门市价）
  2. 约 ¥620 上下（当日散客公开渠道可售的最高弹性房价）
  3. ¥1,280 × 0.5 = ¥640
  4. 取两者平均 ¥950
答案：B　BAR 是「当日散客公开渠道可售的最高弹性房价」，必须贴近真实成交水平。用虚高的门市价当锚，会让所有折扣率失真、渠道价格打架。
3.2

房型价差：反映价值差异

触发条件

搭建价格体系时设定，每季度用表 F 校验。

涉及表

表 F · 表 J

判定规则

价差要反映可感知的价值差异。经验值：相邻房型价差通常 15%–25%；套房等高等级房型可更高，但必须与设施差异匹配。价差太小 → 客人都升级、低价房空置；价差太大 → 高价房无人问津，沦为升级池。

执行动作

① 列出各房型的面积、景观、设施、权益差异；② 按差异化定相邻价差（15%–25% 起）；③ 用表 F 生成全房型价目表；④ 每季度用实际销售结构校验（若某房型长期售罄或长期空置，说明价差错了）。

案例

某店高级房比标准房只贵 ¥20（480 vs 500），客人普遍加价订高级房，导致标准房 OCC 仅 55%、高级房 98% 并多次超售。另一极端：套房定标准房 3 倍价，长期 OCC 不足 20%，沦为升级池。（案例3）

自测题

标准房 ¥520，套房设施差异不足以支撑 3 倍价差，却定价 ¥1,580。最可能的结果是？

  1. 套房供不应求
  2. 套房长期空置，只能靠免费升级消耗，无法产生应有收入
  3. 标准房卖不动
  4. 两者都卖得很好
答案：B　价差必须与可感知价值匹配。定太高，高价房无人付费，只能当升级池消耗掉，既损失收入又让真正愿意付费的客人觉得不值。
3.3

渠道价差与价格一致性

触发条件

每次上新渠道、每次调价时检查。

涉及表

表 H

判定规则

同一房型在各渠道的挂牌价（含税总价）必须一致——这是表 H 的红线。渠道差异只能用权益实现（积分、免费取消、延迟退房、早餐），不能用公开牌价差异化。破价会被平台降权、被客人比价后投诉，还会永久拉低价格锚。

执行动作

① 全渠道牌价保持一致；② 直销差异化用权益（会员价同价但送权益）；③ 每周做一次渠道价格巡检；④ 发现破价立即纠正并追责。

案例

某店为提直订，在官网公开挂比 OTA 低 ¥120 的牌价。结果被平台降权、OTA 客人大量投诉，且价格锚被永久拉低，直销占比不升反降。（案例3/表H要点）

自测题

想让官网比 OTA 更有吸引力，正确做法是？

  1. 官网公开挂更低的牌价
  2. 牌价保持一致，但官网送积分、免费取消、延迟退房等权益
  3. 官网牌价低 5%，算不上破价
  4. 下架 OTA 只留官网
答案：B　公开破价违反表 H：会被平台降权、被客人比价后投诉、并永久拉低价格锚。用权益做差异化，既能吸引直订又不伤价格体系。

环节 4　数据采集与市场细分

4.1

字段治理：细分市场字段必填

触发条件

上线收益管理前必须完成；之后每月核查填报质量。

涉及表

表 E · 表 I

判定规则

PMS 的细分市场字段必须可用且被正确维护，历史日度数据至少 24 个月。字段缺失会导致所有客人都归为「散客」，差别定价无从谈起。这是收益管理的地基，比调价更重要。

执行动作

① 梳理 PMS 细分市场字段（散客/协议/会员/团队/OTA/上门）；② 培训前台正确归类；③ 补录或确认 24 个月历史数据；④ 每月抽查填报准确率。

案例

某店 PMS 细分字段长期无人维护，80% 订单都落在「散客」。想给协议客户做专属价却查不出哪些是协议客，只能对所有客人统一定价——价格敏感的协议客与临时的高价散客被同一价格对待，两头不讨好。（案例4）

自测题

上线收益管理的第一步通常是什么？

  1. 立刻调高价格
  2. 补齐并治理细分市场等基础数据字段
  3. 换一套 RMS 系统
  4. 多投 OTA 广告
答案：B　没有干净的细分数据，就无法区分客群、无法差别定价、也算不准 No-show。补数据是地基工程，先于一切调价动作。
4.2

客群细分：按渠道/提前期/敏感度分群

触发条件

数据治理完成后进行，每季度回顾。

涉及表

表 A · 表 E

判定规则

至少按三个维度分群：渠道（OTA/直销/协议/团队）、提前期（远期/中期/临期）、价格敏感度（弹性大/小）。不同分群给不同价与不同库存。远期客计划性强、可用早鸟锁量；临期客更急、肯出高价。

执行动作

① 按渠道拆分间夜与均价；② 按提前期分档（如 T-30 以上 / T-7~30 / T-7 内）；③ 估算各分群的价格弹性；④ 对不同分群配置不同价与库存。

案例

某店不分提前期，商务客（平均提前 21 天）与临时散客（平均 1.5 天）同一挂牌价。结果早鸟客没有折扣激励转向竞对，临近的高价需求又无房可卖，远期预定量比竞对低 18%。（案例4）

自测题

商务客平均提前 21 天预订、价格敏感；临时散客提前 1.5 天、价格不敏感。应该怎么定价？

  1. 统一挂牌价，简单省事
  2. 远期放早鸟价锁量，临近留给肯出高价的临时客
  3. 远期定高价，临近打折
  4. 只做临时客生意
答案：B　提前期是最有效的分群维度之一：远期需求用折扣换确定性（早鸟锁量），临近需求更急、愿意付高价，应保留库存承接。统一价会两头都丢。

  1. 超售太激进
  2. 超售参数没按实际 No-show+取消 重算，导致大量可补卖的房间白白空置
  3. 应该完全不超售
  4. 房量太小
答案：B　超售要按「No-show + 取消」的合计来算。实际 20% 却只超售 5 间（约 1.6%），意味着大量本可补卖的房夜被浪费。当然超售上限还要受房量 5% 等约束。

5.1

判定规则

预测的最小颗粒度是日型，不是月、也不是周。基线 = 历史同期 × 季节系数 + 当前在手预订。周末与平日的差异往往远大于月与月之间的差异。

自测题

  1. 月度
  2. 周度
  3. 日型（D1–D4）
  4. 季度
答案：C　周末与工作日的需求差异，往往远大于不同月份之间的差异。颗粒度只到月或周，就会把周末的溢价空间和平日的放量需求一起抹平。

案例

距入住还有 10 天，某日在手仅 45%，收益经理判断需求疲软准备降价。但 Pickup 追踪显示过去一周该日在手从 22% 涨到 45%，增速是同档日型的 1.8 倍。若降价 12%，最终 OCC 96% 但 ADR 比应达水平低约 9%。（案例5）

自测题

  1. 降价促销，因为在手量低
  2. 守价或提价，因为增速显示需求强劲
  3. 保持不变，等满房再说
  4. 大幅提价 30%
答案：B　在手量的绝对值会骗人，增速才是先行指标。增速远高于历史同档，说明需求正在快速涌入，此时降价等于把后期的钱提前送掉。
5.3

事件叠加校准：模型补不了的部分靠人工

涉及表

表 I · 表 A

判定规则

预测模型基于「去年同期 + 平滑」，无法捕捉物候与事件驱动的日期位移（花期、迁徙、马拉松、展会日期变动）。必须建立本地事件日历并人工叠加校准，否则会系统性失准。

3 月初系统预测（基于去年 2 月平滑外推）显示需求平缓，按平峰定价。结果樱花提前一周开放，需求突然爆发，等反应过来已满房但价格没提上去——3 月 RevPAR ¥556，若按实际需求定价可达 ¥605，少赚约 ¥44 万。（案例13）

  1. 历史数据不够多
  2. 物候/事件驱动的需求日期位移，模型无法捕捉
  3. 系统出了故障
  4. 竞对恶意干扰
答案：B　花期、迁徙、赛事这类事件的日期每年会前后移动 7–14 天，而模型基于「去年同期 + 平滑」，天生捕捉不到这种位移。这是结构性缺陷，必须靠事件日历人工补位。

环节 6　日型划分与库存分配

6.1

日型划分：至少四档

触发条件

每年做全年日型日历；重大事件确认后更新。

涉及表

表 A · 表 B

判定规则

日型至少分四档：D1 峰值日（展会/节假日核心日，可提价 20%+）、D2 高涨日（周末/旺季）、D3 平峰日（普通工作日）、D4 低谷日（淡季/周日）。不同日型的定价与库存策略完全不同。

执行动作

① 做全年日历，逐日标注日型；② 叠加展会/节假日/赛事；③ 不同日型配不同价格档与库存策略；④ 每月复核。

案例

某店全年只用「平日/周末」两档价格。展会三日需求可支撑 ADR ¥980，却按周末价 ¥720 执行并全部满房——三日少收入约 320×3×(980−720)×0.9 ≈ ¥22 万，而这样的日子一年只有几次。（案例6）

自测题

一家酒店全年只分「平日价」和「周末价」两档，最大的风险是什么？

  1. 价格太复杂，客人看不懂
  2. 峰值日（如展会）被按普通周末价卖掉，白白损失最大的溢价机会
  3. 员工记不住
  4. 系统不支持
答案：B　只用两档会把一年中最好的几天（展会、节假日核心日）按普通周末价卖掉。这些日子需求刚性、价格极不敏感，是全年溢价空间最大的窗口，损失不可逆。
6.2

嵌套库存：高价房型包含低价房型余量

触发条件

每次配置房型库存时。

涉及表

表 B

判定规则

嵌套式库存控制：高价房型的可用量应包含其下所有低价房型的剩余量，卖出后逐级扣减。这样既保证高价房型不会被过早关闭，又保证低价房型不会被高价需求挤占。

执行动作

① 按房型等级建立嵌套关系（套房 > 高级 > 标准）；② 高价房型可用量 = 自身 + 所有下级余量；③ 卖出后从最低可用级开始扣减；④ 每日核对。

案例

某日高级房售罄、标准房 OCC 仅 61%。想订高级房的客人被拒，而标准房大量空置；前台临时手工升级又造成账目混乱，整体 OCC 仅 78%。（案例6）

自测题

某日高级房已售罄但标准房还空着 40%，最可能缺的是什么机制？

  1. 动态定价
  2. 嵌套式库存控制（高价房型可用量应包含低价房型余量）
  3. 超售机制
  4. 渠道管理
答案：B　没有嵌套，各房型库存互不相通，就会出现「高价房卖完了、低价房还空着」的结构错配。嵌套让高价房型可以吃掉下级的剩余量。

  3. 再等一周
  4. 直接取消整个团队单
答案：B　预留不设时限或到期不释放，会把本可散卖的房量长期锁死。约定就是约定，到期释放并立即补挂渠道，才能赶上散客需求窗口。

环节 7　动态定价

7.1

提价触发：什么情况下该提价

触发条件

每日 08:30 查表时判定；临近时每日两次。

涉及表

表 A · 表 C

判定规则

提价三条件（满足两个即可启动）：① 在手 OCC 高（旺季 ≥75%，平峰 ≥65%）；② Pickup 增速快（高于历史同档）；③ ARI < 100（价格还落后市场）。动作：小步多次，每次 2%–3%，观察 3 天；单日累计不超过 8%。同时设 OCC 刹车线。

执行动作

① 查表 A 确认当前日型的建议档位；② 满足提价条件则小步提价；③ 记录进调价台账；④ 3 天后复核 OCC 与 ARI，跌破刹车线立即暂停。

案例

320 间酒店展会前夜预测满房，本店 ADR ¥680、竞组 ¥820，RGI ≈ 87。收益经理担心掉量不敢提价，结果确实卖满（96%）但按竞组水平单日少收入约 ¥3.2 万，ARI 仅 83。（案例7/案例11）

自测题

出租率已经 88%，但 ARI 只有 94（价格低于市场）。最该做什么？

  1. 降价保住出租率
  2. 提价——OCC 高且 ARI<100 说明卖便宜了，小步多次提价
  3. 维持原价不动
  4. 关闭低价渠道
答案：B　「OCC 高 + ARI 低」是最典型的「卖满了却没卖贵」。此时提价的风险最小、收益最大，应小步多次（每次 2%–3%）提价并观察 OCC 反应。
7.2

降价触发：什么情况下该放量

触发条件

每日 17:00 巡检时判定；临近低谷日提前 1–2 天。

涉及表

表 A · 表 H

判定规则

降价（放量）三条件：① 在手量明显低于历史同档；② Pickup 增速慢或为负；③ 已临近（T-3 以内）且剩余房量多。动作：不动牌价，用限时尾单 + 隔离渠道（会员/小程序/最后一分钟产品）释放，避免污染公开价格。

执行动作

① 确认剩余房量与临近程度；② 只在隔离渠道做限时尾单；③ 设定释放时点（如 17:00 后）；④ 底线：成交价 > 变动成本。

案例

周日（低谷日）17:00 还剩 22 间。变动成本 ¥180，当前 BAR ¥544。全场 5 折公开甩卖会拉低品牌价格带；坚持不降则最终只卖出 3 间，19 间空置归零——白丢 19×(544−180) ≈ ¥6,916 的贡献毛利。（案例5）

自测题

低谷日临近还剩一批空房，正确的处理方式是？

  1. 全场公开 5 折甩卖
  2. 牌价不动，用限时 + 隔离渠道（会员/小程序）的尾单清仓
  3. 坚持不降，宁可空着
  4. 只卖给团队
答案：B　公开甩卖会永久拉低价格锚；完全不卖则房晚归零。正确做法是牌价不动、用限时与隔离渠道清仓，且成交价只要高于变动成本（本例 ¥180）就比空着强。
7.3

守价判定：什么时候什么都别做

涉及表

表 A · 表 I

判定规则

守价条件：在手量处于合理区间（平峰 50%–75%）、Pickup 增速与历史同档接近、ARI 在 95–105 之间。此时最优动作是什么都不做，继续观察。频繁调价本身就是成本：会打乱价格预期、增加前台执行负担、让客人困惑。

执行动作

  1. 小幅提价 3%
  2. 小幅降价 3%
  3. 什么都不做，保持守价并继续观察
  4. 大幅提价抢占市场
答案：C　三个指标都处于健康区间时，最优动作就是不动。频繁调价会打乱价格预期、增加执行成本，反而损害收益。守价也是一种决策。

环节 8　库存控制与超售

8.1

触发条件

涉及表

表 B

判定规则

  2. 关闭低价房型库存并设 MinLOS，把房留给高价需求
  3. 降低 BAR 吸引更多订单
  4. 只留套房
答案：B　需求强时继续开放低价房型，等于用低价把高价需求挤走。关闭低价房型 + 设最短住期，才能把有限的房量分配给肯出高价、住得久的客人。
8.2

表 E

判定规则

超售是算出来的：超售上限 ≈ 预期 No-show + 取消的合计，且受两个硬约束——① 不超过预期 No-show（避免步行）；② 通常不超过房量的 5%。参数必须按月重算：线上预付占比提高、取消政策收紧都会让 No-show 显著下降。

执行动作

① 按月统计 No-show + 取消率；② 按表 E 由参数反推标准超售间数；③ 特殊时期（展会/演唱会）单独下调；④ 保证订房（担保卡）优先保留，不参与超售扣减。

案例

沿用的旧参数 No-show 12%，超售 20 间；但因线上预付占比提高，实际 No-show 已降至 6%。结果 3 位客人到店无房，赔付 3×(680×1.5+300) = ¥3,960，另有一位保证订房客人公开投诉。（案例8）

自测题

房量 320，统计出的预期 No-show + 取消合计为 6%（约 19 间）。超售应该怎么定？

  1. 完全不超售，绝对安全
  2. 超售约 16–19 间（不超过预期 No-show，且不超过房量 5%）
  3. 超售 40 间，最大化收益
  4. 超售 5 间，凭经验
答案：B　不超售会把可补卖的房白白浪费；超售超过预期 No-show 则必然步行。正确区间是「不超过预期 No-show」且「不超过房量 5%」——本例约 16 间（房量 5%）。注意两个约束取小值。
8.3

步行应急：已经超售过度了怎么办

触发条件

一旦发生步行风险立即触发（表 L 优先级 1）。

涉及表

表 L · 表 E

判定规则

保证订房（担保卡）优先保留，超售扣减从不保证的订单开始。若已发生步行：① 立即安排同档或更高档合作酒店；② 承担差价与交通；③ 赔付标准约为房费 1.5 倍 + ¥300 安置费；④ 24 小时内复盘并下调超售参数。

执行动作

① 启动表 L；② 优先安置保证订房客人；③ 按标准赔付并承担交通；④ 事后 24h 复盘，重算超售参数；⑤ 主动跟进客人，争取把负面转为补偿满意。

案例

3 位客人到店无房，赔付约 ¥3,960，另有一位保证订房客人在社交平台发长文投诉——直接损失可量化，口碑损失难以估量。（案例8）

自测题

已经出现到店无房的客人，处置时最优先保护谁？

  1. 先到先得
  2. 保证订房（担保卡）客人优先保留房间
  3. 价格高的客人优先
  4. OTA 客人优先
答案：B　保证订房（担保卡已扣款）具有最强的履约义务，walk 掉这类客人既违约又最容易引发公开投诉。超售扣减应从「不保证」的订单开始。

环节 9　渠道与团队策略

9.1

渠道开关与配额：按日型分配

触发条件

每日 08:30 执行；旺季每日复核。

涉及表

表 H · 表 B

判定规则

渠道不是全开或全关，而是按日型给配额：需求强时压 OTA 房量、把库存留给直销与高价渠道；需求弱时放开 OTA 走量。原则是「旺季控渠道、淡季借渠道」。

执行动作

① 按日型设定各渠道的房量配额；② 峰值日压 OTA、开直销；③ 低谷日放开 OTA 与尾单频道；④ 每周复盘各渠道净贡献（NRevPAR）。

案例

某店 OTA 占比 55%，月房费 ¥360 万，仅佣金就 ¥10.7 万/月。若在峰值日压 OTA 量、把库存倾斜给直销，可显著降低渠道成本。（案例3）

自测题

展会三日（需求极强）应该怎么处理渠道库存？

  1. OTA 全开，能卖多少卖多少
  2. 压 OTA 配额，把房量优先留给直销与高价渠道
  3. 关闭所有 OTA
  4. 只留一个 OTA 独家
答案：B　需求强时不需要靠 OTA 走量，反而应该把有限的房量留给净贡献更高的直销与高价渠道。原则是「旺季控渠道、淡季借渠道」。
9.2

直订提升：用权益，不用降价

触发条件

持续进行；每月复盘直订占比。

涉及表

表 H · 表 B

判定规则

提直订 = 权益差异化 + 库存倾斜，绝不等于公开降价。直销可给：会员价（同价送权益）、免费取消、延迟退房、积分兑房、免费升级。牌价必须与 OTA 一致（表 H）。衡量用 NRevPAR 与直订占比。

执行动作

① 设计直销专属权益（不动牌价）；② 优质房型优先给直销；③ 前台引导 OTA 客人下次直订；④ 把 NRevPAR 与直订占比放进日报首屏。

案例

某中端酒店 OTA 62%、直销 20%。通过权益差异化 + 库存倾斜 + 前台引导，6 个月后 OTA 降到 41%、直销升到 44%，NRevPAR 提升 9.4%，年化净利润增加约 ¥38 万。（案例3）

自测题

想提高直销占比，以下做法正确的是？

  1. 官网公开挂比 OTA 低的价格
  2. 牌价保持一致，但直销送积分、免费取消、延迟退房等权益
  3. 把所有 OTA 下架
  4. 给 OTA 更低的价换曝光
答案：B　公开破价违反表 H，会被平台降权、被客人比价后投诉，还会永久拉低价格锚。用权益做差异化，才能既提直订又不伤价格体系。
9.3

团队置换与综合贡献：接不接要算两笔账

触发条件

每次团队/会议询价时。

涉及表

表 G · 表 K

判定规则

判断团队单接不接，要算两笔账：① 置换损失 = 被挤掉的散客净收益（按「本可卖出的间夜」算，不是按满房算）；② 综合贡献（表 K）= 客房 + 餐饮 + 会场 + 设备。全服务酒店尤其不能只看客房。

执行动作

① 算本可散卖的间夜数；② 算置换损失；③ 加餐饮会场算综合贡献；④ 尝试把部分房量挪到低谷日以降低置换损失；⑤ 记录进决策台账。

案例

450 间五星酒店，500 人年会要 380 间夜、房价 ¥680（BAR ¥1,180）。表面看客房亏 ¥19 万；但按实际可散卖的 279 间夜算置换，再叠加餐饮会场（约 ¥52 万），综合净收益 +¥55 万——只看客房会误拒。（案例1）

自测题

一个会议单报价低于 BAR，但会带来可观的餐饮与会场收入。判断是否该接，主要看什么？

  1. 只看客房单价差
  2. 置换损失（按本可卖出的间夜）+ 表 K 综合贡献（客房+餐饮+会场）
  3. 领导或销售的意见
  4. 对方结算周期
答案：B　全服务酒店的会议价值 = 客房 + 餐饮 + 会场 + 设备。只看客房会把划算的会误拒；但置换损失要按「本可卖出的间夜」算，按满房算会高估损失。

10.2

案例

  2. 价格异常自动告警（偏离 BAR ±30% 即告警）
  3. 等客人投诉再处理
  4. 每周核对一次
答案：B　损失大小取决于发现速度。3 小时 20 分才发现损失 ¥21.7 万，10 分钟内熔断则约 ¥2 万。告警 + 熔断 + 巡检三层都要有，但告警是第一道。
10.3

涉及表

判定规则

案例

某日表 A 建议提价（在手高），表 C 显示 ARI 已 108（高于市场）。收益经理与销售争执不下拖到下午，临时凭感觉选了「不提价」，当日满房且竞组价位更高，少赚约 ¥8,000——更糟的是流程变成「谁嗓门大听谁的」。（案例10）

  1. 听收益经理的
  2. 听销售的
  3. 按表 O 的优先级仲裁（表 A 优先级 3 > 表 C 优先级 4）
  4. 今天不做决策
