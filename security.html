站点防护现状与升级路径

RMC 收益管理社区 · 2026-10-02 · 内部说明，勿外传

一、先讲结论

GitHub Pages 是纯静态托管，没有服务器，所以它做不了真正的登录鉴权。
现在装上的访问门是浏览器端检查：能挡住搜索引擎、随手点开链接的人、地址被转发扩散； 挡不住懂技术的人直接下载源文件。
如果您的要求是「资料绝对不能被拿到」，那必须换到有服务器的托管平台（见第五节）。

下面把「现在已经做了什么」「挡得住什么」「还差什么」逐条列清，方便您判断要不要继续投入。

robots.txt 这次是「策略反转」，您要知道为什么

原来的 robots.txt 写的是全面放行所有 AI 爬虫（GPTBot、ClaudeBot、Perplexity、百度等），目的是让 AI 搜到并引用您的内容，提升曝光。

但现在的实际情况是：站点上放着您的教材全文（508KB）、15 张判定表 PDF、讲师版 PPT、报价策略、定价模型——这些是私有资产。原来那份配置等于把它们主动送去给 AI 训练。

所以已改为全站禁止抓取。如果将来您想重新做公开引流，必须先想清楚：哪些页面可以公开，哪些必须留在门后。两件事不能同时要。

场景挡得住吗说明

直接下载 zip / pptx / pdf 成品挡不住门只管页面，管不到文件本身

四、还差什么：38 个成品文件仍是敞开的

访问门管页面，管不到直接下载的文件。目前全站有 38 个可直接下载的成品，只要有人猜到地址就能拿走，合计约 3.0MB。最值钱的几个：

撤下这些文件是有代价的取舍，不是免费操作。
撤下后，resources.html、series.html、books.html、coach.html 等页面上的下载链接会失效。
换句话说：要么成品可下载（方便客户，但也方便别人拿走），要么撤掉（安全，但您自己看东西也不方便）。
目前维持原状未撤，等您决定。

五、如果您要真正的加密级保护

这需要把站点迁到有服务器的平台，由服务器在返回内容之前先验身份。三条路：

路线 A · Cloudflare Access（免费，推荐先试）

Cloudflare 的「零信任」网关，可以直接保护 *.pages.dev 域名，不需要买域名。配置大概 20 分钟：

  1. 注册 Cloudflare 账号（免费）
  2. 把 crm/ 目录推到 Cloudflare Pages（免费，生成 xxx.pages.dev 地址）
  3. Zero Trust → Access → Applications → Self-hosted，域名填您的 pages.dev 地址
  4. 登录方式选「One-time PIN（邮箱验证码）」，策略里只填 3984557428@qq.com
  5. 之后任何人访问都会先收到 Cloudflare 的验证页，输入邮箱、收到验证码才放行
优点：真正的服务端鉴权，连源码都拿不到；服务器在请求到达前就把人拦了。
代价：服务器在境外（*.pages.dev 无大陆节点），您自己访问可能慢或偶尔打不开；静态站 55MB 每次都是从境外拉。
适合：资料以「自己查阅 + 少量熟人」为主，且能接受访问偶尔不稳。

路线 B · 腾讯云（国内最稳，但要备案）

项目里已经备好了 deploy_tcb.sh（CloudBase 静态托管）和 国内可用性与备案方案.md。国内访问速度是所有方案里最好的，但需要：买域名 → 提交 ICP 备案（10–20 天）→ 开通环境 → 上传。

优点：国内访问快、稳定，微信里打开体验好。
代价：备案要 10–20 天且需要您本人操作；纯静态托管同样没有登录功能，还得额外配一层网关。
适合：确定要长期公开运营、且主要客户在国内。

路线 C · 只保护最值钱的（最省事的折中）

接受站点页面继续公开，但把教材全文、书系、PPT、判定表 PDF这四类撤出公开仓库，只在您需要时从本地取用或用带密码的压缩包单独发。

优点：今天就能做完，几乎零成本，立刻堵住最大的漏洞（整包被人拿走）。
代价：客户要看样章就没法自助下载了，要您手动发。
适合：您现在还没到需要公开站点引流的阶段——按您当前进度（尚无第一个学校案例），这其实是最匹配的选择。

六、我的建议

先做路线 C，把四个高危成品撤下来。理由：它今天就能做完，能立刻堵住「整包被拿走」这个最大风险，而且不动您的页面结构。

暂时不要为了登录去迁 Cloudflare。您的站点现在几乎没有外部流量（还没有第一个学校案例），迁移带来的访问不稳定风险大于收益。等您真有了客户、站点开始被人访问，再上 Cloudflare Access，那时它的价值才显现。

等真到了要长期公开卖课的那天，再走路线 B 备案 + 国内托管。那时访问速度才会真正影响成交。
